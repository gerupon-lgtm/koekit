# 曲とパーツの操作をそろえる追補

## 目的と範囲
画像で報告された「完成した部品を編集できないように見える」「つくりかけをここから聴けない」「保存曲の位置が触るたび変わる」を修正する。現在の曲一覧→曲全体→部品編集を使い、画面は追加しない。JST表示と現行の色・文字・44px操作・8px間隔、縦スクロール削減を維持する。

## 実装の単位
- [x] part-view.js：部品の確定音／草稿プレビュー・並び使用中を既存checkpointから読取専用で判定。無音は理由を表示し、試聴では確定・保存・並びを変えない。
- [x] project-workflow.js：部品メニューの主操作を聴く／編集する／並びに入れるで統一。旧形式の完成品も未使用なら同じ部品を編集。元の編集とコピー編集を別の操作として表示。元のフレーズを直すと、曲の全使用箇所へ反映することを発案者が承認。草稿もコピー時に保持。
- [x] song-store.js／song-library-view.js／song-workflow.js：新しく作った順で固定、同時刻はIDで安定。曲一覧へ並び・部品・途中の件数と、聴く対象を表示。古い再開先表示を置換。
- [x] ブラウザ：完成・草稿・空・確定と草稿の両方・旧曲・配置済み編集・コピー・キャンセル・一覧順固定・リロード・試聴内容・縦配置を確認。既存音源・保存失敗・競合・候補確定を回帰。
- [x] 規約／仕様レビュー、全Nodeを最大5ファイルずつ、キャッシュ更新とJST版、Pages公開・公開ファイル一致・通常URLを確認。

## 操作の説明
曲全体の上は「曲の並び」、下は「この曲のパーツ」。空の並びで全体再生できなくても、各パーツから聴けることを示す。パーツのメニューでは再生内容を表示し、確定音と草稿が違えば選べる。並びへ入るのはオッケー済みの内容で、草稿を試聴しただけで確定しない。

元を編集する操作と、元を残してコピー編集する操作は別にする。コピーを「編集する」とだけ表示しない。元を編集した場合は、同じpatternIdを使う全配置へ反映する。コピーや一か所の派生版は別IDとして維持し、元編集の対象に含めない。並びのカードの「ここだけ直す」は従来どおり一か所だけを変える。

保存曲一覧は一行が一曲。並びがあれば「曲の並び」を聴き、並びがなければ部品を選ぶ。部品が一つでも再生する対象を示してから聴く。編集・改名・表示切替・試聴による自動保存では曲の位置を動かさない。

2026-11-01：元の編集とコピー編集、草稿のその場の試聴、保存曲順固定の3点を発案者が再確認し、実装を承認。「元編集で5箇所すべてに変更が反映」の意味で合意。


## 保存と反映の設計

- `project.editingOriginalId` を任意追加。利用者が「このフレーズを編集する／つづきをつくる」から元を開いた場合だけactiveIdと同じIDを記録し、確定内容を同じpatternIdへ同期する。同じIDの配置全箇所へ反映し、別IDのコピー・一か所派生は変更しない。
- オッケー前はcheckpoint.draftだけを保存し、配置の確定音を維持。コピーを作ると元編集指定を解除する。元編集指定のない古い編集画面からの変更は従来の独立コピー保護を維持する。
- 使用箇所数をメニューと編集画面に表示。保留中の一か所修正がある間は元編集を無効にして、草稿と別更新の混在を防ぐ。一か所だけ直す既存導線は保持する。
- 草稿の再生は既存checkpointを一時復元し、入力候補を含むプレビューを複製して鳴らす。曲・部品・確定状態へ書き戻さない。確定音と違えば「つくりかけ／オッケー済み」を選べる。無音なら聴くを無効にして理由を示し、つづきの編集には入れる。
- 曲一覧はcreatedAt降順・同時刻はID順。updatedAtは更新日時として保持するが並べ替えには使わない。並びの件数・パーツ数・草稿数と、再生するのが並びかパーツかを表示。部品が一つでも、曲の並びがなければ再生対象を示してから聴く。
