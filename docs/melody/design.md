# サエズリズム 基本設計

版：0.3／2026-10-01。状態：保存・再開、伴奏・個別コード・音色、4／8小節ループ録音を実装し、依頼に従い既存試作URLへ公開した。[実装記録](implementation-log.md)、[今回の検証](workflow-implementation-plan.md)、[配信記録](preview-deployment.md)参照。診断のprototypeは互換用にv25を維持し、workflowRevisionで更新を識別する。実機音響・本アプリの全機能は未完了。
要件の正典：[要件定義書v1.2](../requirements-melody.md)。今回の操作合意：[伴奏・制作・録音・保存仕様v0.3](accompaniment-workflow-spec.md)。共通規約：[実装ガイド](../implementation-guide.md)。人向け：[設計サマリ](summary.md)。実装入口：[handoff.md](handoff.md)。

追加合意と現実装：音符なしの未確定コードは、再読み込み復元と保存枠の対象にしない。既存曲のコード編集はつくりかけとして保存する。初期10曲の上限は `saezuri/song-store.js` の `SONG_LIMIT` で一元管理する。コード変更は画面では1小節、データでは開始位置と長さのtick区間を持つ。後の1拍（4tick）／2拍（8tick）切替に備えた処理・保存形式とした。

保存の現実装は IndexedDB `koekit-saezuri` の `songs`／削除済みID用 `deleted`、レコード schemaVersion=1。`data` に checkpoint（確定部分／つくりかけ）、フレーズ棚・確定配置・仮の配置・テンポ・メロディー音色を持ち、コード・パート音色は pattern 内に保持する。録音波形・解析の全フレーム・セッションUndoは永続化しない。下記の将来用 Song モデルの全フィールドや原曲／直前版の更新操作を実装済みと扱わない。ハナウタ確定時の録音詳細破棄は、発案者への再相談待ち。

2026-10-01の音量指定は `probe/saezuri/volume.js` の VolumeControls／AudioMixer に実装。既存「設定」内の1行にカウント・伴奏・全体を0／50／100／150／200%で配置し、`localStorage['saezuri.mix.v1']` に端末共通設定として保存する。既定100%は従来の音量。カウント／伴奏のgainをmasterへまとめ、メロディーもmasterへ接続する。試聴・進行候補・つなげる・一覧・伴奏ループ・録音カウントで共有し、変更時は15msで遷移する。標本ごとの出力ピーク制限を最後に置き、先読み・オーバーサンプリングは使わない。録音の声の入力ゲインは変更せず、消音時はカウント音響実測を行わない。将来の各パート・メロディー単独の曲ごとmixとは別の実装であり、保存スキーマ・Undoへ含めない。

入力位置の移動だけでは空の曲を作らない。明示的に入れた休符を位置移動と区別するため、編集状態の `hasRest` と確定チェックポイントの `hasRest` を保持し、Undo／取消／復元へ引き継ぐ。おてほんは独立した練習として保存せず、利用者が「フレーズにする」を選んだ時点から作品として保存する。満杯でも練習は可能だが、作品への登録とおためしのコピーは上限を確認する。

2026-09-28の画面試作は[v21画面構成](screen-navigation-v21.md)を参照。トップから制作／連結へ分離し、設定シートとタブ内フレーズ配置を実装。永続保存の設計採用や本アプリ完成とは区別する。

## 1. 範囲・設計判断

既存コエキットへの増分設計。素のHTML/CSS/ES Modules、ビルドなし、端末内音声処理、タッチ操作、2段階確定、PWAを継承。作曲を楽しむ作品であり、採点・称号・レベルロックを持ち込まない。サーバー・ログイン・音声アップロード・共有は導入しない。

印なしの利用ルールは合意済み要件。【設計】は要件を満たす実装判断、【想定】は可逆的な調整値、【要確認】は未合意の操作・ライフサイクル案。未合意を実装済み・承認済みと扱わない。

### 入力品質・未決事項の分類

ML-001〜015、初版／後続、最大10曲・16配置・128＋1小節、候補と確定、音域外原曲の採用、認識失敗時の戻り先は定義済み。画面遷移・保存失敗・競合を本書で補う。設計全体を止める技術ブロッカーはないが、ハナウタと音源品質は実機試作が先行条件。利用者判断が必要な案は11節へ集約し、依存部分の本実装前に判断する。未決のため関連しない設計を停止しない。

| 項目 | 判断・理由 |
|---|---|
| 時間表現 | 【設計】1拍=4tick（16分=1、8分=2）。整数位置を全表示・再生で共用し、BPM変更で音価を変えない |
| 保存 | 【設計】専用IndexedDB。曲全体と保存世代を同一トランザクションで更新し、最大10件と競合を検査。既存作品の保存を移行しない |
| 音 | 【設計】専用Web Audio出力エンジン。共通sfxの時計・内部状態へ依存しない。音源は差替え可能なアダプタ |
| 譜面 | 【設計】譜面用中間データと描画アダプタを分離。VexFlow等の追加依存は未採用。ML-T01で方式を選び共通ガイドと整合させる |
| ハナウタ | 【設計】言葉認識とは別のAudioWorklet＋解析Worker。外部APIなし。音声の16kHz化を無条件に流用しない |
| UI | 共通フォント・メニュー部品・発話案内を使用。作成／譜面／曲の連結で同じドキュメントを編集 |

## 2. 構成と処理境界

【設計】新規ルートは `/saezuri/`。相対参照でカスタムドメイン／サブパスの双方に対応する。以下は実装予定であり、現存ファイルではない。

| モジュール | 責務 |
|---|---|
| `saezuri/app.js`・`state.js` | 画面・区間・世代番号。入力と非同期結果の所有権 |
| `document.js`・`commands.js` | 音符／配置の検証、候補、確定、取消、差分とundo |
| `speech.js`・`vocabulary.js` | 共通音声ファクトリとの接続、区間別文法、語彙データ |
| `storage.js` | DB検証、10件上限、世代比較、保存・削除・復元 |
| `music/arrange.js`・`assist.js` | 伴奏・おすすめ・見直し・ととのえる。純粋関数／必要ならWorker |
| `music/catalog.js` | 進行・ジャンル・役割・音色・コード種・調整値・版のデータ |
| `audio/transport.js`・`voices.js` | 音声時計、予約、停止、音色、チャンネルミックス |
| `capture/worklet.js`・`analyzer.js` | 標本時刻付き捕捉、有声／音高推定、音符化 |
| `ui/editor.js`・`score.js`・`sequence.js` | 同じ曲モデルの表示、選択・候補・再生位置 |
| `tutorial.js` | 3種類の案内、実操作による進行、再受講 |

各編集処理は `validate(document, command) → candidate | {code, details}`、`commit(document, candidate, baseRevision) → nextDocument` に分離。試聴・候補生成で確定版を変更しない。利用者が入力・編集した候補は未確定の草稿として別保存でき、自動生成した比較候補の試聴だけでは草稿を作らない（2026-10-01合意）。再生・解析は `{sessionId, baseRevision}` を受け、古い完了通知を破棄する。サーバーAPIはない。

## 3. データ・永続化

### 曲と音符

【設計】DB名 `koekit-saezuri`、schemaVersion=1。`songs`（idキー）と `preferences` を使用。曲を一体のレコードにし、音符だけ保存できて伴奏が古い等の中間状態を避ける。

| データ | 主な項目・制約 |
|---|---|
| Song | id、schemaVersion、revision、title、createdAt/updatedAt（UTC ISO）、displayTimeZone（IANA）、tempo（60〜180）、meter=[4,4]、genreId、patterns、placements、ending、channels、history |
| Pattern | id、familyId、revision、bars（4/8）、gridStep（2通常／1取り込み）、key={tonicPitchClass,mode}、notes、arrangement、source（manual/hum/example）、captureProvenance |
| Note | id、startTick、durationTick、midi、spelling、origin（input/detected/completed/adjusted）、confidence（検出時のみ）。start>=0、duration>0、end<=bars*16 |
| Placement | id、patternId。最大16。配列順が演奏順。単体制作でも最初の配置を1つ保持する案はQ1で確認 |
| Arrangement | progressionId、コード列、rhythmId、生成イベント、generatorVersion。採用結果と手動指定した小節を保存し、再読込・再提案・ジャンル変更で無断上書きしない |
| Chord | root（0〜11）、quality、bass（0〜11）、spelling。キー外も許容 |
| Ending | enabled（初期false）、mode=auto/custom、customChord、resolvedChord、演奏パターン版。1小節で配置上限の別枠 |
| Channel | slotId、role、instrumentMode=auto/custom、instrumentId、mix=soft/normal/clear、muted。旋律もチャンネルとして扱う |
| History | originalBeforeAdjust（最初の調整前版）、previousRevision（直前版）。詳細な更新契機はQ1。再帰的にhistoryを複製しない |
| Draft（画面名：つくりかけ） | 【設計】確定版と別の未確定音符・休符・コード変更・解析済み録音結果、候補・編集位置・入力設定、baseRevision。元の確定版なしの新規草稿も識別する。Undoスタック・生音声・AudioNodeは含めず、復元だけでcommitしない |
| Preferences | tutorialId別のseen/completed/skippedと版。曲とは別。マイク設定は既存共通キーを使う |

整数tickで単音の半開区間 `[start,end)` を検査。隣の音の開始=endは許容。休符は音符のない区間で表現し、休符入力の確定はカーソルの移動コマンドとしてundo可能にする。小節またぎは1音のまま保持し、譜面でのみ分割・タイ接続する。

通常C4〜C6はMIDI60〜84。声の音域外原曲は保持し、表示を拡張する。数値表現はMIDI0〜127を格納できるようにするが、実機の検出可能音域は別途測定。範囲外の壊れた保存値をクランプして受理しない。

単音・最小tickから導かれる最大音符数は通常8小節64音、取り込み編集8小節128音。曲は最大2048発音＋伴奏イベント（配列の共有による省略は可）。これは音符の追加上限ではなく時間制約からの上限。未配置パターン数の上限は未合意で、16配置をパターン保存数制限へ転用しない。

### 配置ごとの編集

【設計】配置が同じpatternIdを参照している間も、通常編集のcommitは対象配置用のパターンを複製して参照先を差し替える。familyIdは同じ由来を追跡する。単独編集済みを含めるか曖昧にならないよう、「おなじパーツも変更」では対象配置を一覧プレビューして確定する（細部Q2）。全対象を1コマンド・1回のundo・1保存トランザクションにする。

### 保存と競合

- 最大10件は新規／複製の保存トランザクション内で件数を確認。別タブから同時作成しても11件目を保存しない。IDは作成操作ごとに固定し、再試行で重複曲を増やさない。
- **合意**：入口を開いただけで新規枠を作らず、音符の有無を先に見て「音符がある、または伴奏・コードを明示的に確定した」で保存開始する。音符なしの確定伴奏でも続きから制作可能。作品／草稿のデータ差分で作業を判定し、高さ・長さの選択だけは未編集。コード変更へこの例外を広げない。音符なしの未確定コードは、確定まで再読み込み復元の対象にしない。
- 更新は期待revisionを検査し不一致なら `SAVE_CONFLICT`。古いタブから新しい版を無断上書きしない。削除済みIDへの更新で曲を復活させない。
- 作品／利用者が作った草稿のデータ変更でdirtyにし、非同期保存を直列化する。【想定】250ms程度のまとめ書き。終了前に完了を待ち、保存成功表示はtransaction complete後。pagehideのみに保存を依存しない。不慮の停止後も最後に保存成功した草稿から復帰する。
- **合意**：通常の「やめる」は保存後に確認なしで終了。次回その作品を開いた時につくりかけがあれば「つくりかけがあるよ。どうする？」と表示し「つづきから つくる」／「つくりかけを けす」を選ぶ。草稿を捨てる際は確定版を保持、確定版のない新規草稿だけはレコードを削除して枠を空ける。確定伴奏のみの曲にも確定版がある。
- 保存失敗はメモリ内編集と以前の保存内容を維持。**合意**：保存失敗中だけ終了前に「まだ ほぞんできていないよ」と表示し、「もういちど ほぞん」／「つくるのを つづける」／「ほぞんせず やめる」を選べる。競合の復帰方法はQ1残件で、保存失敗の操作合意を競合処理の承認へ広げない。
- 音声波形、MediaStream、AudioNode、タイマー、再生位置は保存しない。【失効：2026-10-01】未確定候補を一律に保存しない案は、利用者が編集した候補を確定版と別のDraftへ保存する合意に変更。ハナウタは解析済み音符・補完印・必要な診断だけを残す。Undoはメモリ内のみで終了・再読込後には復元しない。
- DBを開けない／未知schemaの場合は読み書きを止め既存値を保持。自動初期化しない。利用者向け再試行を用意。
- 日時はUTC保存、表示は端末IANA zone・不明時Asia/Tokyo。保存の順序・競合はrevisionで判断し端末時計に依存しない。日付入力・期限・日付別判定なし。

## 4. 画面・操作

### デザイントークン

共通の正典は[画面設計](../screens.md)。`"M PLUS Rounded 1c", "Hiragino Maru Gothic ProN", "Yu Gothic UI", "Meiryo", sans-serif`、自前woff2、既存インラインSVGアイコンを継承。新アイコンライブラリは加えない。【想定】本文16px/1.6、400/700、主要操作48px以上。音名・残り拍数はより大きくする。

ロゴ色は[採用素材](assets.md)の確定値。ラベンダーを本文の薄い文字色に流用せず、本文・選択・補完印は形／ラベルと濃い色も併用する。ロゴ・小鳥は縦横比維持・全体表示。小鳥の単体透過素材は別途制作する。

| ID | 画面・表示 | 入口→正常な次 | 戻る／中断・空／エラー |
|---|---|---|---|
| M-S01 | タイトル：ロゴ・小鳥・つくる・作品・練習 | トップ→S02/S08/S09 | ホームへ。曲0件は新規案内。続きからの配置は設計案 |

| M-S03 | 作成：メロ音量3段階、残り拍、小節、グリッド／譜面、候補、長さ、確定、再生 | 音入力→候補→確定。S04〜07へ | 候補取消・undo・おわり。空曲も編集可能。超過は候補保持し確定無効 |
| M-S04 | 曲の連結：パーツ一覧、配置順、現在パーツ、任意エンディング | 選択→試聴→配置確定、編集はS03 | 16配置なら追加無効、並べ替え／削除は利用可。送り末尾は停止案 |
| M-S05 | イメージ・ととのえる・おすすめ・見直しの比較 | 伴奏はおすすめ1＋比較3の最大4案を同じ画面で試聴→明示採用（2026-10-01画面確認後の変更）。小節ごとのコード変更も可 | このまま／取消→元を保持。手動コードを無断上書きしない。候補なしは説明して戻る |
| M-S06 | くわしく：音色、各ch音量・ミュート、臨時記号候補、ミックス初期化 | 変更→保存→元画面 | 音色おまかせとミックスを戻す操作を分離。再生中はタッチのみ |
| M-S07 | ハナウタ：準備→カウント→録音→解析→候補 | 結果の試聴・修正・調選択→採用→S03 | ほぼ未検出は破棄し準備へ。拒否はタッチ入力へ。途中中断はQ3 |
| M-S08 | 作品：名前・小節・時間・試聴・編集・複製・削除 | 一覧→編集／複製、削除は確認 | 空は新規案内、保存上限は既存編集と削除を案内。再生停止を固定 |
| M-S09 | 段階別チュートリアル | 初回／再受講→実操作→元の機能へ | 初回からスキップ可。既存作品を上書きしない練習領域。保存の扱いQ1 |

コード選択機能は、調に合う候補を押して試聴／「ほかのコード」でルート＋13種類／「ベース」で分数コード／「オッケー」で確定の流れに合意。**UI仮採用**：小節コードを押すと下から選択シートを開き、選択小節を見ながら操作する。配置・タップ寸法・表示量・操作性は実際のUIを見て相談し、本採用扱いにしない。

【設計】小画面で常時表示するのはトップのメロ音量／拍、小節切替、編集領域、確定・再生操作。音色・支援・詳細設定はシートへ分離。音程と時間を同時に極小セルへ詰めず、音高選択＋時間選択のタッチ経路を用意する。16分は拍ごとに拡大でき、ピンチ・ドラッグを必須にしない。PCは広い表示を許容する。

チュートリアルは画面を覆い続けず目標と次操作だけをポップアップ。見直しヒントは入力中は目印のみ。「このまま」は該当フレーズ・和声のfingerprintが変わるまで抑制。削除や変更がなくても毎回同じヒントを出さない。

スマホ390×844を主確認、320px幅・短い横画面・文字200%・PCでも全操作への到達を確認する。短い画面での必要なスクロールは許容し、停止ボタンや確定理由を隠さない。画面全体の横スクロールは避ける。

## 5. 音声受付と状態機械

| 区間 | 言葉認識 | 音高捕捉 | タッチ・次への条件 |
|---|---|---|---|

マイクの所有者をspeech/capture/noneで1つに限定し、移管前に停止・解放を完了する。共有マイクOFFイベントは録音にも適用する。非同期getUserMedia完了が古い場合は取得トラックを即停止する。再生終了時は音源の余韻も止めてから受付を戻す。

`sessionId`を開始・停止・画面遷移で更新し、認識結果・解析・音源ロード・再生endedの旧世代通知を無視する。マイクOFFからの古いresultで候補を追加しない。

確定語は既存のオーケー／オッケーを継承。音名・高さ・拍数は要件どおり。数字だけを音名に補完しない。選択済み音符の長さのみ変更等の追加語彙は区間を限定して設計案として検証する。未確定時のもどす、削除確認、16分の呼び方はQ2。許可される語を共通voice-guideで表示し、未採用の語を案内しない。

### 相対音高の音声編集（2026-09-27追加）

発案者の要求により、選択音の高さ変更を「たかく／あげる」「ひくく／さげる」で音声でも指定する方向。続く「思い付きなので、操作のしやすさが優先」を優先条件とする。通常はコードトーン移動、「はんおん」を添えた指示は半音移動という方式は比較案であり、確定ではない。キーの音階モードを追加する合意でもない。

【比較案】コードトーン方式を採る場合、選択音の開始位置の伴奏コードを参照し、上下方向の最も近い構成音を候補とする。「はんおん」はその1回だけ有効。未確定候補があれば候補の高さを起点にする。コードによって移動幅が変わる分かりにくさと、半音方式で細かな操作が増える負担を比較する。どの方式でもタッチと共通の編集候補へ接続し、開始・長さ・他音を保持、オッケーで確定する。元の音名入力の「うえ」はオクターブ指定を維持する。再生中・ハナウタ取り込み中は言葉認識を行わない。

コード未設定の自由制作での通常移動は比較事項。操作性優先の補足と実装への了承を受け、v14試作では半音上下に統一した。譜面・ブロック選択と上下ボタン、共通Voskによる音声語彙を接続した。コードトーン既定方式の採用確定とはしない。

### 番号での選択とスマホ表示（v15）

v14実機で選択自体は動く一方、選択位置と反復発話の負担が問題になった。ブロックへ発音順の番号を振り、音声「10ばん」またはタップで直接移動してから編集する。先頭・末尾移動も追加。番号はタイの表示断片ではなく元の音符に対応し、選択はUndoへ積まない。日本語Voskへは既存deliveryと同様の空白区切り漢数字・番で登録する。

スマホでは操作欄に選択番号・小節・音名を常設し、ブロックと高さ制限した譜面枠を近接配置する。譜面・番号列の内部を選択音へ追従し、横画面では操作と譜面を左右配置する。仮編集・確定・Undoの規則は維持。本アプリ全体のスマホ導線は引き続き未完成。[v15試作記録](humming-v15.md)参照。

### 仮編集とセッション履歴（2026-09-27追加合意）

取り込み後の編集は確定版と仮の作業版を分ける。複数音の変更を作業版へ蓄積し、そのメロディ全体をプレビューできる。音の選択・変更・試聴では確定版を上書きせず、全体確定で明示反映する。確定後も作業版の編集を再開できる。v14で作業版・確定版・Undo履歴を分離して実装した。全体確定で主音列を更新し、編集画面は開いたままにする。

Undoは編集セッションのメモリ内に保持する。仮編集だけでなく確定を挟んだ編集も戻せるようにし、全体確定で履歴をクリアしない。【設計】作品／取り込み候補の編集開始から「やめる」で閉じるまでを1セッションとする。再生・停止・表示切替・一時的な非表示は終了としない。終了時にUndoだけを破棄し、作品を削除しない。再読込・タブ終了後に履歴は復元しない。v14の仮変更を捨てる終了は試作時の履歴として保持し、**2026-10-01合意の本仕様では、つくりかけを保存して終了し、次回作品再開時に続ける／捨てるを確認する**。保存失敗時だけ終了前の確認とし、詳細は3節。

保存用Historyの原曲・比較版とUndoスタックは別のデータとする。未確定作業版の試聴を許可するよう従来の再生ガードを見直すが、再生による暗黙確定と、再生中の言葉認識は行わない。コードトーン／半音の方式は引き続き使いやすさで比較する。

## 6. 音楽・伴奏・支援

### 再現できる候補生成

【設計】入力は旋律・選択調・拍位置・進行カタログ。伴奏生成は端末内ロジック、外部生成AIなし。C／Am各4候補程度を選定し、他調では移調する。候補は強拍・持続音・フレーズ終端への和声適合を重み付けし、全候補の点数が低い場合も「正解」を断定しない。重みと進行は試聴調整用データへ置く。

**2026-10-01合意**：カタログからおすすめ1案＋比較用最大2案を提示し、全体進行を試聴→確定。まず1小節1コードで、確定後も小節ごとに自由変更できる。手動指定の小節を識別し、再提案やジャンル変更で無断上書きしない。旋律変更ごとに進行を自動変更せず、選び直しは明示操作。音符なしでコードを先に確定し、同じ伴奏へ通常入力／ハナウタを乗せる。

生楽器風と電子音を両方用意して混合できる。各ジャンルのおまかせ編成と個別指定を扱い、個別音色・ミックスは曲に保存し、ジャンル変更でも保持する。具体音源・編曲・初期音色は試聴採用まで未確定。

ジャンルの楽器・リズムをカタログに分離する。個別音色を維持し、おまかせのみ更新。チャンネルはinstrumentIdではなく安定slotId（例chord-main/chord-layer/bass/drums）で対応付ける。同じroleでも複数あれば別slotIdを持ち、1つの音量を全パートへ誤配布しない。新slotはnormal/unmuted。姿を消したslotの設定保持はQ2で扱う。

進行変更・ジャンル変更・ととのえるは候補ドキュメントへ計算する。元の音高・開始・長さを保つ操作と、明示的な旋律調整を混同しない。設定変更中に原曲が更新された場合は候補を作り直し、古い版へ採用しない。

### 3つの支援

- おすすめ：次の音高＋長さを最大3候補。終端・重なりにより配置不能な候補を除外し、なめらか／変化／終止の違いを付ける。選択はcandidateで、確定は別操作。
- 見直し：局所的な跳躍・持続する和声衝突・オクターブ異常の可能性を示す。前後フレーズと修正案を同じテンポ・伴奏で比較する。正誤・採点なし。
- ととのえる：音のみでは開始・長さ・休符を保持。音とリズムではこれらも変更できるが小節数・単音・編集単位を維持。結果の差分を表示し、採用前に原版を保持。

ハナウタの補完は採用前の候補生成の例外であり、既存曲を自動補正する許可ではない。補完した音はorigin=completedで識別する。

### 曲末と譜面

【設計】コード種はルートからの半音間隔で定義：major=[0,4,7]、minor=[0,3,7]、7=[0,4,7,10]、maj7=[0,4,7,11]、m7=[0,3,7,10]、sus4=[0,5,7]、dim=[0,3,6]、aug=[0,4,8]、6=[0,4,7,9]、m6=[0,3,7,9]、add9=[0,4,7,14]、m(add9)=[0,3,7,14]、m7♭5=[0,3,6,10]（2026-10-01追加）。13種を小節ごとの変更と曲末で共用し、m7♭5をdimと混同しない。add9へ7thを自動追加しない。ベースは別音で指定でき、C/FのFをCへ補正しない。ボイシングはジャンル用データで、全音を同じオクターブに押し込まない。

エンディング初期なし。追加は16tickだけ、旋律は延長しない。customChordをイメージ変更で消さない。autoで異なる調のパーツをつなぐ場合の終止調はQ2。

譜面はト音記号＋旋律＋上部コード名。小節線・拍のグループに合わせて音符を分解し、タイ／休符／臨時記号／16分を表す。描画音符と元noteIdの対応を保持し、分割タイで再発音を作らない。範囲外原曲は加線・表示移動で確認できる。2026-09-27の追加指示により、取り込み試作では譜面の音符を選択して編集欄で修正する操作を追加する（下記）。譜面上のドラッグ編集、伴奏各パートの楽譜、印刷は追加しない。

## 7. 再生・ミキシング・ハナウタ

### 再生時計

【設計】`t(tick)=anchorAudioTime+(tick-anchorTick)*60/(BPM*4)`。音と表示で同じanchorを参照する。曲中のテンポ変更なし。開始前に音源・表示を準備し、AudioContextが動作した後で開始時刻を決める。DOMの描画回数を曲位置にしない。

【想定・検証前】予約先読み100〜200ms、予約周期25ms、開始猶予0.3〜0.5sを比較。固定の正解値にしない。遅延時に過去イベントを一斉発音せず停止・復帰を案内する。rAFは現在位置表示用。Web Animationsを使う場合も小節境界でAudioContext位置と照合し、8分36秒の曲でずれを測る。見た目の補助タイマー増設だけで済ませない。

停止・送りは世代を更新し、先読み音源、持続音、余韻、予約タイマーと表示アニメーションを停止。送りは次の配置先頭の共通anchorで再開する案。停止ボタンは画面固定。BPM変更は停止時のみ適用する案Q2。

メロディ／伴奏各voice→音色の基準音量→channel gain（3段階）→mute gain→masterへ接続する。音符のベロシティは編集UIへ追加しない。ミュート解除はmix段階を復元。音色の違いで同段階の聴感が極端に変わらないよう試聴調整。headroomを確保し、最大編成のクリッピングを試験する。低モーションでも拍・現在位置を表示する。

### 音高取り込み

1. 共通言葉認識を停止・解放。音声許可、入力・出力の準備、同一sessionIdを確認。
2. AudioWorkletの標本番号／sampleRateを捕捉時間の基準とし、メインスレッド到着時刻で音符開始を決めない。入出力が別時計なら開始アンカー対応と長期差を測定する。
3. 従来録音は8拍カウント後の4小節だけ分析。ループ録音は録音指示の次のループ先頭から4／8小節の1フレーズだけ分析し、待機中は練習とする。既存メロディーは採用まで保持し、録り直し中は伴奏だけ再生する。予約・カウント・伴奏は同じ音楽時計へ接続し、入力の標本時計と遅延補正を分ける。実測基準音の確保、回り込み・Bluetooth遅延は未検証で、既存補正を保証値として流用しない。
4. 【想定】自己相関系／YIN系などの端末内推定を比較。有声判定とpitch confidenceを分離し、休符・有声不明・音高確定を区別する。算法の採用はT01で決定。
5. 前後関係による補完は有声不明区間に限定する。ほぼ未検出はトースト→今回破棄→準備へ。先頭・末尾で片側しかない補完の扱いはT01で検証しQ3で判断。
6. 半音化して最近傍16分へ開始・終了を丸める。【想定】同距離は後方、0tick音価は1tick候補へ。ただし重なり・末尾超過を作らない。連続同音の切れ目、丸め衝突は解析候補の目印付き調整とし試聴する。詳細は測定後に定める。
7. 選択した録音フレーズの末尾を越えない（従来4小節、ループ4／8小節）。全体オクターブ移動を試し、収まらない原曲も採用可能。C4〜C6へ強制折返ししない。
8. 取り込みストリームを停止し、結果の試聴・修正・採用。音声生データはセッション終了時破棄。採用するまでは既存曲を変更しない。

【試作v13・2026-09-27追加】v12の同一入力が長音7音／細かい変化19音／ならしなし33音となる結果を受け、発案者は自動調整を区切り、後編集で補う方針を了承。[取り込み候補編集](humming-v13.md)で譜面タッチまたは一覧選択から音高・開始・長さの置換、分割、隣接音の結合、削除を候補化し、試聴・確定・取消・undoを提供する。同じ検出フレームからの3方式はそれぞれ編集状態を保持し、解析元の記録は変更しない。16分単位・単音・末尾制約を守り、休符をまたぐ結合は拒否する。数値診断JSONの端末内読込も試作範囲。生音保存・外部送信は追加しない。v13の実装・結合検証と配信状態は試作記録を参照。本アプリ統合やQ1〜Q3の合意を意味しない。

## 2026-09-28 v20試作：通常作成の共通化

M-S02の自由／イメージ入口から、同じ作成・編集セッションへ入る。通常入力は`source: manual`・`gridStep: 2`・C／Am、C4〜C6白鍵の候補とする。既存のハナウタ編集の半音変更・16分解像度は維持。候補は`entry`として確定音列・カーソルと別に保持し、1音の確定にdocumentのstale検査と共通Undoを使う。無効候補は保持して確定／試聴を拒否する。小節数・キー・伴奏の変更は従来の仮編集として比較・確定する。

音名＋長さのVosk語彙は通常入力の区間だけ追加し、元の編集語彙と共存。語彙切替で古い結果を破棄する。実声の精度は未確定。スマホは譜面・カードと入力を縦配置し、候補の近くでオッケー、表示は譜面／カード／両方。1小節の横幅適合・試聴追従は共用。

伴奏は各調4進行と4ジャンル・3リズムの試聴用データ。旋律と同じAudioContext anchorで予約し、別の発音数を記録する。ジャンルはリズム・進行を初期値へ替え、BPMは明示ボタンで適用。旋律は保持する。全パートのミックス・支援・連結・作品保存の完成ではない。[v20の実装と検証](normal-creation-v20.md)、[通常作成の監査](normal-creation-plan.md)を参照。
