# 伴奏確定後の鍵盤への移行（2026-10-10）

発案者の画像報告と指示に基づく配置変更。伴奏確定後もイメージ選択が上部に残り、鍵盤までのスクロールが増えていたため、演奏時の表示を短くする。

- 通常の「イメージからつくる」は、伴奏を選んでいる間だけ「音楽のタイプ／はやさ／ふんいき」と「別のパターン」を表示する。オッケー後に閉じ、同じ行の「伴奏をえらび直す」で再び開く。再生・録音中も選択欄を閉じ、選び直しは無効にする。
- 調と4／8小節は前面に残す。折りたたみと再表示は曲・候補・Undoを変更しない。声で新しい伴奏候補を出したときは選択欄が開く。採用済みの曲を再開した場合は閉じて始める。
- メロディーの音色選択を鍵盤のすぐ上に常設し、練習状態と横1行に収める。演奏に使う既存の `#instrument` を移動して再利用する。再生・録音・解析中は既存の状態管理で無効にする。設定シートを開いている間は同じ選択部品を設定へ移し、閉じると鍵盤上に戻す。つなげる画面の音の設定も維持する。
- イメージ欄を開いた状態から確定したとき、鍵盤と下げ／元／上げが画面下の停止欄に隠れていれば、その分だけ画面を送る。既存の操作部品・色・丸みと8px以上の操作間隔を使う。
- 詳細検証表示 `view=full` と旧編集表示は従来の選択欄を維持する。折りたたみのために、保存形式・音源・コード・音符の処理を変更しない。

PC Chromeで、8小節の伴奏確定→折りたたみ→再表示→再生成、表示変更だけで曲が変わらないこと、鍵盤・オクターブ操作の視界、前面音色の実発音、再生中の無効化、1つだけの選択部品の設定／前面への移動、保存と再読込、320／390／844／1280pxを確認済み。既存のイメージ再生成・手動コード保持・取消・タップ録音・鍵盤・模擬音声操作も成功。保存曲と音の出る5シートの閉じる／停止位置・8px間隔・スクロール・再生中の閉じる／Escapeも横断確認した。公開用キャッシュ更新後の同じUI検証、版一致とキャッシュ刻印のNode検証も成功。実機の操作性は本人の再確認を続ける。

主な実装は `image-mode-controls.js`・`keyboard-controls.js`・`screens.js`、配置は `image-mode.css`・`keyboard.css`。検証は `scripts/test-saezuri-keyboard-access-browser.cjs`。公開時はキャッシュ識別子とホームの開発版表示を更新し、公開URLでも確認する。
