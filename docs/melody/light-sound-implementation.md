# スマホ優先の軽量音源試作（2026-10-03）

対象はサエズリズム。発案者の「進めてください」に基づく実装。スマホで安定して制作・再生できることを最優先とする。現行より音楽的な音色を、その条件の範囲で調整する。事前合成は不採用、自然なディケイとリリースを保つ。別PJへの互換性・フィードバックは採用条件にしない。

## 試せる操作

- [比較ページ](https://koekit.sikumilab.com/probe/light-sound/)：同じ音高・長さ・音量指定で「軽い音」「さらに軽い音」「今の音」を比較する。1／2／4／6／8／12／16音、保持／反復、Am → F → C → Gのカウント・ドラム付き演奏を選べる。
- エレピ・ベルはC4／E4／G4、柔らかいベースはC3／E3／G3を個別に試聴する。音源を切り替えて同じボタンで比較する。
- [軽い音で制作](https://koekit.sikumilab.com/probe/saezuri/?sound=light)、[さらに軽い音で制作](https://koekit.sikumilab.com/probe/saezuri/?sound=simple)：既存の鍵盤・ハナウタ・伴奏ループ・タップ録音・編集・保存・音声操作を使う。
- [通常の制作](https://koekit.sikumilab.com/probe/saezuri/)は従来音源。URLの指定はその画面だけに適用し、音源方式を保存曲に追加しない。未知の指定は従来音源へ戻す。
- 「途切れなし／あり」は完了した試聴に本人が付ける評価。途中停止・画面非表示・発音エラーは未評価のまま記録し、成功扱いにしない。機種名を入力してJSONを端末へ保存できる。結果・音声の送信は行わない。

公開状況は引き継ぎの公開確認記録を参照する。実装・PC検証と、スマホでの採用判断を区別する。

## 発音方式

すべてブラウザ標準のOscillatorNode・GainNode・BiquadFilterNodeを使った演奏時の合成。提供6 OP DSP、音色JSON、PCMサンプル、Workerでの事前生成を読み込まない。独立した比較ページはnoindex／nofollow、トップのリンクを増やさない。アプリへ音色編集・波形選択UIを追加しない。

| 既存の音色ID | 軽い音 `light` | さらに軽い音 `simple` |
|---|---|---|
| piano | サイン波のcarrier＋modulator、2発振器のエレピ試作 | フィルター付き三角波、1発振器 |
| wood | サイン波2発振器のベル試作 | サイン波1発振器 |
| soft | フィルター付き三角波1発振器の柔らかい音 | 同じ構成 |
| sine | サイン波1発振器 | 同じ構成 |
| lead | フィルター付きノコギリ波1発振器 | 同じ構成 |

カウント・ドラム・音量の3経路は既存処理を利用する。FMのmodulatorは周波数AudioParamへ接続し、別の音として出力しない。高音域は変調量を弱め、modulatorの周波数が出力rateの35%を超える場合はcarrierだけにする。これだけで折り返し雑音が全面的に解決するとは扱わない。TX81Z／DX7II実機の波形・EG・位相変調を再現した音源ではない。

音量のディケイは音符長に依存しない時定数、リリースは離鍵時点の音量から減衰させる。エレピ420ms、ベル300ms、柔らかい音220ms、サイン200ms、リード180ms。FMの変調量にも独立した減衰を付ける。鍵盤の長押しは同じ音源を保持し、指を離すとリリースする。音符の長さを変更してディケイ全体を伸ばす処理はしない。

ProbeTransportは発音ごとの実際の終了時刻を使う。ループ境界で音源を作り直さず、前の周期の余韻と次の先頭を重ねる。有限フレーズは最後の余韻まで待ってから終了する。明示的な停止・画面非表示・音声中断では、鍵盤のリリース中の音も含めて即時に止める。終了後はノードを切断する。

方式の切替・生成済み譜面・コード・保存データは独立。音符／コード／リズム／進行を間引く自動処理や、スマホの未測定上限に基づく発音打切りは追加していない。端末別の上限は実機確認後に判断する。

## 比較の条件と記録

保持・反復は既定12秒。30／60秒へ変更できる。反復は500ms周期・350msの音符で余韻も重ねる。全方式で同じMIDI、gain、velocity 70を指定。gainは各音 `min(0.08, 0.65 / 押している音数)` で合計の過大なピークを避ける。音源ごとの聴感上の音量が完全一致する補正ではない。

混合の1音はC5の旋律、2音はC5＋C3のベース、以後C4／E4／G4の和音。単音色はC4／E4／G4／C5、ベースのみはC3。コード進行は既存伴奏生成を使い、4小節単位で指定秒数以上へ切り上げ、最後の余韻まで再生する。3小節目以降も上モノを含む。

JSONは方式・条件・開始／終了時刻・sampleRate・状態・本人評価・先行予約・最大タイマー間隔等を記録する。ネイティブノードの処理時間をWorkerで推定してCPU使用率と呼ぶことはしない。`maxVoices` は予約済みのカウント・ドラムも含むtransport管理数、`maxActive`／`maxOscillators` は先行予約・離鍵後の余韻も含むノード所有数で、同時に押す音数そのものではない。音切れの測定値ではない。

比較ページは最大12件だけを画面に表示し、書き出しにはそのページでの全試聴を含む。閉じるは右上、停止は固定フッターの中央、並ぶボタンは10px以上離す。補足・記録は折りたたみ、制作画面のスクロール量は増やさない。

## 検証と採用判断

PC Chromeの自動検証で以下を確認した。本人による試聴評価・Pixel 6a／Chrome・iPhone XR／Chromeでの安定性の確認ではない。

- 2方式×5音色の実際の合成PCM：非無音・有限値・発音開始、音符長によらない初期の減衰、離鍵後の余韻、終了後の無音。低音／高音、velocity、鍵盤保持、開始前の予約取消も確認。
- 実AudioContextの有限フレーズが最後の余韻まで待つこと。3方式の16音保持／反復、コード進行とカウント／ドラム、試聴切替・停止・非表示・JSONの操作。
- 2方式の既存制作画面：鍵盤練習、マイクを開かないタップ録音、候補／オッケー、保存・再読込、伴奏中の鍵盤、ハナウタ待機、停止・非表示での音源解放。
- 3方式×48イメージ伴奏の上モノを実際に合成し、全4小節で非無音・非クリップを確認。通常音源の既存鍵盤・音量回帰、軽い音での8小節ハナウタ・ループ予約取消・再録音後の候補確定待ちも確認。
- 比較画面の320／390／844px、見出しと停止の中央配置、ボタン間隔、横のはみ出しなし。CSS・JS・共有音源のキャッシュバスター経路。
- 既存の制作音声コマンドの回帰は模擬Vosk認識結果で通過。実声・音声認識負荷との併用は実機確認待ち。Windows版WebKitでは画面読込・JSエラーなしを確認したが、Web Audio APIを利用できず、音声の検証はPARTIAL。これをiPhoneでの発音成功として扱わない。

実機ではまず混合6音の反復を3方式で比較し、次に必要な音数・コード進行・制作画面での録音等を確認する。音切れがあれば低い音数だけで結論を出さず、両端末で同じ条件を比較する。低遅延の鍵盤、ループの先頭・余韻、録音・音声認識との併用、30／60秒と複数回の使用を含める。音楽性・最大発音数・本採用はその結果で判断する。
