# 試聴の音切れと入力表示（2026-10-18）

## 利用者からの報告

Pixel 6a／Chrome・マイクONで、初回と繰り返しの両方に、カウントや旋律の出だしの欠け・途切れがある。マイクOFFとの比較は未確認。試聴の声での聴き直しと、通常制作での次の入力位置への移動が分かりにくい。

その後、見るノート表示（カード／五線譜）と、押す入力表示（カード／鍵盤）を独立して選ぶ方向を追加。表示切り替えとして既存の入力・録音を再利用する。鍵盤の入力方法まで変更する話ではない。

## 再現と対策

- `test-saezuri-tutorial-audio-stall-browser.cjs`：曲の先頭で画面処理を700ms止めると、旧実装は `SCHEDULER_LATE` で停止し、試聴が途中で切れる。修正前の失敗と修正後の成功を確認。
- `test-saezuri-audition-navigation-browser.cjs`：準備済みのマイクが、試聴開始時に解放・再取得される。旧実装で取得回数1→2の失敗、修正後は1のままを確認。音切れの実機原因がこれだけであるとは断定しない。
- 8小節までの短い試聴は、音符を生の音源のまま最初に予約する。長い曲は1秒以上の先読みを使い、開始前の余裕を最低0.6秒確保する。事前の音色合成や音符長・減衰の変更はしない。ループ録音の時刻の仕組みは変えない。
- 画面更新と、チュートリアルで使う制限付きの認識の準備を先に済ませる。出力に無音を流して音の時計が進むことを確認してから、カウントの時刻を決める。聞こえるカウントは引き続き四分音符4つ。
- 試聴時は準備済みのマイクの経路を保持する。認識の受付／停止と区間ごとの語彙制限は維持し、マイクOFF・画面外・録音等での解放も維持する。
- 途中で音声が中断した場合や先読みが間に合わない場合は、試聴画面にも理由と聴き直し方法を示す。計測記録には予約方式、初期予約時間、最初のカウントまでの余裕を残す。

## 声の操作

試聴画面では「きく」「もういちど」「もういっかい」が同じ動きになり、表示中の対象をカウントから聴き直す。メロディーだけを選んだ場合はその選択も保つ。「おてほん」は見本を新しく開き直す。画面を閉じた通常の「きく／もういちど」は制作中の曲を聴く。通常制作にも受付中だけ声の試聴案内を表示する。導入では完成形の見本を使う。

試聴画面に声ON/OFFと、その時点で受け付ける語を表示する。準備中・受付休止中には発話を促さない。音の追加や確定を再生中に受け付けるようには変更しない。

## 通常制作の表示と入力位置

- 制作画面の前面で、ノート表示（カード／五線譜）と入力表示（カード／鍵盤）を独立選択。初期は従来どおり五線譜と鍵盤。表示の好みだけ端末内に記憶し、曲や候補、Undoには保存しない。
- カード入力は、既存の音名・長さ・休符→オッケー。鍵盤入力は、既存の練習・タップ録音。録音・演奏の処理を置き換えない。従来、1音ずつ入力できる手動制作が4通りの組み合わせの対象で、取り込み後の編集と鍵盤録音の制約は維持。
- カード表示は既存の共通表示を再利用し、休符と小節・和音を示す。表示枠の中を動かし、ページの縦方向を大きく増やさない。再生中のカードは黄色、五線譜はピンクを維持する。
- カード入力では鍵盤を閉じ、長さの選択を1列にまとめる。鍵盤を使う操作は入力表示を鍵盤へ切り替える。入力表示は再生・録音中に変更できないが、ノート表示は試聴を続けたまま変更できる。
- 入力はオッケーで自動的に次へ進む。前面の半拍移動と、中央の入力位置ボタンから小節・拍を選べる。五線譜には「ここ」の目印を置く。移動だけでは曲やUndoを変更しない。音の候補がある間は場所の移動を止める。
