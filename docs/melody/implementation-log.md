## 試作の見方

1. 音色は正弦波（比較基準）、ピアノ風、木琴風、やわらかいシンセ。いずれも本試作のWeb Audio合成であり、楽器の採用音源ではない。C3・半音・反復・小節またぎ・C7・終音の作例を同条件で比較する。
2. 開始猶予350/500ms、先読み100/150/200msを選べる。音と拍位置は同一AudioContextのanchorを参照する。タイマー遅延で過去音をまとめて発音せず停止する。固定停止ボタンは常時表示。
3. 「空の4小節」→音高／長さ→候補→オッケーで入力。候補未確定の再生は拒否。試作はC3〜C7を試せるが、これは通常制作の音域仕様を変更するものではない。
4. マイクONで「カウントして取り込む」。2拍間隔×2＋1拍間隔×4の計8拍後、4小節分をsample indexで切り出す。カウント音とOS音声処理の要求を切替比較する。入力音のスピーカーモニターはしない。
5. 解析結果は別候補に表示。試聴だけでは元の音列を変更せず、「試作の音列に採用」で明示反映。波形は保存せず、解析Worker終了で破棄。記録は数値・音符・入力条件のみ。
6. 画面非表示・停止・マイクOFFで捕捉を中断し、古いgetUserMedia/解析結果は不採用。この安全な試作動作をQ3の本実装承認と扱わない。

## 音高解析の比較と残る制限

旧方式では解析窓に開始偏りがある。4096標本の前方窓を先頭時刻へ割当てると、48kHzで0.5〜1.5秒だけ鳴るC4正弦波の検出が0.448〜1.4933秒となった（レビューで再現）。180 BPMでは開始tick6が5になる。OS入力遅延とは別の算法上の問題であり、固定補正値を足す処理は導入していない。

`measure-saezuri-pitch.mjs` で同じ合成入力を比較した結果：2048標本窓は開始−9.3ms／tick6／解析95.2ms、4096標本窓は−52ms／tick5／201.8ms、8192標本窓は−137.3ms／tick4／484.8ms（hop1024、Windows Node、1回）。短い窓の実声・低音・雑音への影響はまだ比較できていないため、単一の正弦波結果で本実装の方式を決定しない。

継続検証で `analyzeSamples` をWorker・測定スクリプトで共用し、音高窓とは別に最初の1024標本のRMSで無音を判定する `energy-gated` 案を追加。試作の詳細条件から `window-start` 旧方式と比較でき、測定記録にも方式名を残す。4096標本窓の同じC4入力で開始−9.3ms／tick6へ改善（解析202.3ms、1実行）。44.1/48kHz・C3/C4/C6の開始／終了、180 BPMの16分低音2つの間の16分休符を検査。新規9テストとブラウザWorkerの実出力で旧方式 `[5,13]` と比較案 `[6,12]`（開始tick,長さtick）を確認。

**残る不成立条件**：48kHz、C4を0.5〜1秒、無音なしでG4を1〜1.5秒に切り替える合成入力では、0.9387〜1.0027秒をC3と誤検出する。180 BPMで存在しない16分音符が入る。前方窓へ異なる音高が混ざる問題で、無音判定分離では解決しない。測定スクリプトはこの入力も出力し、`unexpectedMidi:[48]` を可視化する。テスト39件通過はこの誤検出の解消やV1達成を意味しない。

さらに比較窓を試作画面で4096／2048／1024標本から選択可能にし、選択値を捕捉→Workerへ渡し計測記録に残すようにした。上記C4→G4では2048・1024の両方で余分なC3が消え、開始tick6/12・各6tickの2音となった。1024標本窓で44.1/48kHzのC4→G4、C3→C4、C4→C3も確認した（2ケース追加、計41）。**本採用は未決定**。短窓の低音下限は `sampleRate / floor(windowSize/2)` に制約され、1024標本・48kHzでは約93.75Hz。実声・雑音・短音・全対象音域での比較が必要で、C3より低い音を無断で要件対象外にしない。試作の初期選択は従来の4096を維持。

## 基礎モデルの継続実装

- 音符置換・削除は候補生成中に元を変更せず、確定後のundoで音符・カーソル・選択を復元する。短縮で消えた音符の選択を解除し、undoでは元選択を戻す。
- `sequence.js` は編集セッション用の純粋処理。A→B→Aの最後だけ編集すると新patternIdへ複製し、他配置・原パターン・familyIdを保持。明示された同familyの対象を全件検証してから1回の確定にする。候補作成後の変更・undo後の古い候補をrevisionで拒否する。削除・並べ替えは16配置到達後も可能。保持パターン20種類・16配置・末尾1小節＝2064tickを検査。
- 追加パターン／配置IDは呼出元が渡す。初期保存枠や編集対象選択UIは実装していない。`undoStack` はDB保存用ではないセッション状態。Song全体のschema・保存競合・永続履歴を実装済みと扱わない。
- 合意済み12コード種の半音間隔と4ジャンル名をカタログへ分離。add9に7thを足さず、C/FのベースFを維持。具体的な進行・リズムデータは未採用。`chordTones` の基準音域は検証用の基本形で、ジャンル別ボイシングではない。
- 継続後：Node4ファイル計39ケース成功。Chromeの模擬取り込み・両方式Worker出力・停止／取消・2段階入力・表示回帰が成功。自動試験に実機の声・主観試聴は含まない。
