## 実装する内容

1. 「イメージからつくる」の表面に、次の3つのプルダウンを配置する。
   - 音楽のタイプ：どうよう・ポップ・ロック・バラード。
   - はやさ：ゆっくり・ふつう・はやい。
   - ふんいき：あかるい・やさしい・かっこいい・かなしい。
2. 言葉の組み合わせから伴奏候補を作る。専門的なコード進行・楽器等の選択を必須操作にしない。詳細設定は必要な時に開けるようにする。
3. 同じ言葉の組み合わせに複数の伴奏パターンを持たせる。「じゆうにつくる」の基本進行候補より多様な伴奏を試せるようにする。和音の弾き方・ベース・打楽器等は、音楽的につながる候補の範囲でランダムに組み合わせてよい。単にノートを無秩序にランダム化する方式にしない。
4. 「別のパターン」ボタンを追加し、同じイメージから伴奏だけを再生成する。別案がある場合は現在と異なる候補を提示する。
5. 再生成時は、メロディーの音高・開始位置・長さ・休符、現在の調・BPM・小節数、手動指定したコードや個別設定を保持する。手動指定を解除する場合は別の明示操作とする。
6. 新しい伴奏は候補として試聴でき、「オッケー」で採用、取消で元へ戻れる。連続再生成では未確定の伴奏候補だけを差し替える。既存のUndoへ接続する。
7. 生成した伴奏は試聴・ループ周回・録音開始で勝手に変化させない。採用した結果を保存し、再読み込み後も同じ伴奏を再現する。乱数を振り直して別の演奏へ変えない。
8. 再生・録音待機・録音・解析中は再生成を休止し、停止後に操作できる。メロディーの入力候補との競合も既存の候補管理に合わせて扱う。
9. 伴奏を先に作った後、既存の譜面入力・鍵盤入力・ハナウタ入力で同じフレーズを制作できるようにする。既存の未編集判定・音符なし伴奏の確定／保存条件を保つ。

現在の「あかるめ／くらめ」は調選択の表示です。今回の4種類の「ふんいき」をその2択へ縮めないでください。タイプ・はやさ・ふんいきを変更したことを理由に、既存のメロディーを勝手に変換しないでください。

## 実装と品質の進め方

既存のHTML/CSS/JS・ES Modules構成、スマホのトンマナ、共通音声層、2段階確定、タッチ操作、端末内処理を維持してください。スマホでスクロールを増やさず、再生成・試聴・確定が分かる配置にしてください。他の担当者の差分は保護してください。

具体的なBPMの対応値、音色、コード進行、編曲データはまだ採用未決です。まず試聴可能な複数の伴奏を用意し、採用案として提示してください。コードの処理が正しく動くことと、音楽的な品質の採用を分けて報告してください。既存の伴奏品質には不満が出ているため、現在の配列を増やすだけで品質改善完了としないでください。

合意済みの言葉・伴奏だけの再生成・候補確定等は再質問せず進めてください。実装中に必要になる未決事項は既存資料と利用者の操作性を基に具体案を作り、試聴・操作確認が必要な点を明示してください。

## 完了の確認

- 3項目の全48組み合わせから有効な伴奏候補を作れ、同じ選択で複数のパターンを試せる。
- 再生成・取消・採用・Undoの各段階で、メロディーと保持対象が変化しない。
- 候補の試聴だけでは確定せず、連続再生成や連打で候補・保存状態が壊れない。
- ループの周回・録音開始・保存再読込で、採用した伴奏が変わらない。
- 鍵盤・ハナウタ・保存再開・手動コード・既存自由制作が引き続き使える。
- スマホ幅で選択・再生成・試聴・停止・確定へ到達できる。
