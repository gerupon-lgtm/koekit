# サエズリズム — 伴奏・制作・ループ録音・保存の仕様

2026-10-01、合意反映版 v0.3。保存・再開、個別コード、音色、4／8小節ループ録音をローカル実装した。コード選択の下シート方式は仮採用で、画面を見て操作性を相談する。音色・編曲の本採用とループ録音の実機品質は未確定。公開版はv25のまま。

合意は[要件定義書v1.2](../requirements-melody.md)と[基本設計v0.3](design.md)にも反映。実装と検証は[今回の実装記録](workflow-implementation-plan.md)と[引継ぎ](handoff.md)を参照する。本書の「提案」「仮採用」「技術検証事項」は引き続き確認対象であり、設計全体の承認を意味しない。

追加合意：音符がない新規曲のコード候補は、オッケー前には再読み込みの復元対象にせず保存枠も使わない。確定済みの作品へのコード編集はつくりかけとして保存する。上限は初期10曲で、後から増やせる構成にする。画面のコード変更は当面1小節単位。内部では開始tick・長さtickを持つ区間で扱い、後の1拍／2拍の変更に備える（1拍=4tick、2拍=8tick）。ハナウタ確定時の細かな録音データ破棄は、実装前に改めて相談する。

## 1. 目的と現在との差

伴奏を聴いて歌う／音符を置くことで、ひとつのフレーズを作れるようにする。メロディーから始めた場合は、合いそうな伴奏候補を提示し、利用者が聴いて選び直せるようにする。画面を開いただけで作業を作った扱いにせず、変更したものを残せるようにする。

| 項目 | v25の実装 | 今回の仕様案 |
|---|---|---|
| 伴奏 | 通常入力にC／Am各4進行・4ジャンル・3リズム | 品質を試聴で見直し、入力方法にかかわらず利用 |
| イメージ入口 | 伴奏を選んで音符を置く | 選んだ伴奏に、譜面またはハナウタでメロディーを乗せる |
| メロディーからのコード候補 | 未実装。調号の推定のみ | 基本進行からおすすめを仮割り当てし、手動変更 |
| ハナウタ | カウント後に4小節録音 | 従来の録音に加え、4／8小節の伴奏ループの次の先頭から1フレーズ録音 |
| 作業の有無 | 編集画面が開いているかで判定 | 内容の変更・入力候補・録音結果等で判定 |
| 保存 | タブ内のフレーズ登録・連結 | 最大10曲を端末内へ自動保存・再開。音符なしの確定伴奏と未確定の「つくりかけ」も扱う |

## 2. 制作の入口と共通画面

### 2.1 イメージからつくる

表示名は「イメージからつくる」を維持する案。説明を「伴奏をえらんで、音を置いたり歌ったりしよう」にする。

1. 調（C／Am）、ジャンル、テンポ、4／8小節を選ぶ。
2. おすすめの進行とリズムを伴奏だけで試聴し、必要なら小節ごとのコードも変更して確定する。
3. 同じ制作画面で「音を置く」または「ハナウタ」を選ぶ。
4. 伴奏とメロディーを合わせて聴き、譜面・カードから手直しする。
5. 確定したフレーズを「つなげる」で配置する。

**2026-10-01 合意（コード進行から制作）**：「イメージからつくる」では、伴奏・コード進行を先に決めて確定し、その伴奏に音符入力またはハナウタでメロディーを乗せられる。音符がまだなくても、明示的に確定した伴奏・コードを制作途中の作品として保存できる（6.2節）。

選んだ伴奏はメロディーを入れた後も保持する。歌った結果を理由に、調やコードを自動で別のものへ替えない。「別の伴奏をためす」から明示的に候補を求められる。

### 2.2 じゆうにつくる／ハナウタでつくる

メロディーから始める入口。音符を置く、またはカウントに合わせて歌って取り込む。その後「伴奏をつける」でおすすめを仮割り当てし、聴き比べて確定する。

通常の音名入力はC／Am・8分単位、ハナウタ由来の編集は半音・16分単位という既存の区別を維持する。取り込み結果を通常入力の8分単位へ丸め直さない。

### 2.3 入力方法を替える時

- 入力方法を替えても同じメロディー・伴奏・テンポを使う。歌った後に譜面で直せる。
- 同時に入力する方法はひとつ。ハナウタ録音中は音符入力と音声コマンドを休止する。
- 録り直しはフレーズ全体の差し替え候補を作る。旧メロディーは採用まで保持する。今回は重ね録りや部分的なパンチインを含めない。
- 再録音中は既存メロディーの再生を止め、伴奏だけを流す。
- おてほんは独立した練習領域とし、作品の保存枠を使わない。作品にする操作を選んだ時だけ登録する。

## 3. ハナウタのループ録音

### 3.1 操作と録音範囲

| 状態 | 表示・操作 | 次の状態 |
|---|---|---|
| 準備 | マイクと出力を準備。準備が完了するまで録音予約不可 | 練習・待機 |
| 練習・待機 | 「伴奏をループ」で何周でも歌って試す。録音ボタンと停止ボタン | 録音待機 |
| 録音待機 | 「スタートまで あと○拍」。取り消し可能 | 次のフレーズ先頭で録音中 |
| 録音中 | 「録音中 1／4小節」等。小節・拍・現在位置を表示。中断可能 | 1フレーズ分で解析へ |
| 解析 | 伴奏ループを停止し、検出結果を作る。旧メロディーを保持 | 結果の確認 |
| 結果の確認 | 新旧の試聴、譜面編集、採用／やり直し | 採用で制作へ。やり直しで練習・待機へ |

「次の頭」は伴奏ループの1小節目。途中の小節頭ではない。録音ボタンを押した次のループ先頭から、選択したフレーズの長さだけ録る。録音終了は自動とし、複数周を連続録音して最良のテイクを選ぶ方式は今回含めない。

**2026-10-01 合意**：ループ録音は制作中のフレーズに合わせて4／8小節に対応する。どちらも利用者がループ中に録音開始を指示した次のループ先頭（1小節目）から録り、4小節なら4小節分、8小節なら8小節分で自動停止する。先頭までは残り拍数を表示する。従来のハナウタ4小節固定からの拡張として要件・基本設計へ反映済み。公開v25は維持し、今回のローカル実装で録音経路を拡張した。先頭直前の指示の詳細も3.2節のとおり合意済み。

### 3.2 カウントダウン

拍単位を主表示とする。例：「スタートまで あと7拍」。最後の4拍は大きく「4 → 3 → 2 → 1」、開始時に「録音中」へ替える。秒数を必要条件にはしない。

**2026-10-01 合意（先頭直前の指示）**：残り4拍未満でも次のループ先頭から録り、もう1周待たせない。残り2拍なら「2 → 1 → 録音中」と表示する。マイクと出力の準備は録音ボタンを押せる状態になる前に済ませ、準備中は録音予約を受け付けない。

ボタンを押した瞬間のタイミングには依存せず、伴奏の先頭を基準に録音位置を合わせる。カウントダウン・伴奏・録音開始は同じ音楽時計を使い、60〜180 BPMで拍の表示を追従させる。

### 3.3 従来の録音・遅延補正・中断

- 伴奏ループを使わないハナウタ入力では、既存の2小節カウント（2分×2、その後4分×4）を利用する。
- 既存の実測遅延補正を録音範囲へ反映し、その後に最近傍16分クオンタイズを行う。BPMに依存する拍の長さと、端末の入出力遅延を混同しない。
- ループ録音で実測基準音をどう確保するかは技術検証事項。伴奏だけを基準に、同じ測定ができるとは扱わない。実測不能時は推定補正の使用を表示する。
- 待機中の取消、録音中断、マイクOFF、画面退出・非表示では録音予約と入力を止め、旧メロディーを保持する。遅れて届いた録音・解析結果は反映しない。
- ほぼ未検出なら今回の候補を破棄して練習・待機へ戻る。次の録音もフレーズ先頭から始める。
- 生音声は端末内で一時解析する。録音ファイルの永続保存・外部送信は行わない。
- 最初の実機検証はイヤホンを基準にする。スピーカーの伴奏回り込みとBluetooth遅延は別に確認し、未検証の精度を保証しない。

## 4. メロディーとコード候補

### 4.1 先に伴奏を選んだ時

調と進行は利用者の選択を優先する。歌った音がコード構成音以外でも取り込み、メロディーを勝手に吸着・移調しない。表示するコードは現在選択した伴奏のもの。歌声からコードを読み取った表示とはしない。

### 4.2 メロディーから始めた時

1. 通常入力は選択済みのC／Amを使用する。ハナウタ・記録読込は旋律から調の候補を示し、利用者が選択できるようにする。
2. 選んだ調へ基本進行を移調し、候補の相性を比較する。
3. おすすめの進行を仮割り当てする。**合意：おすすめ1案＋比較候補を最大2案、合計最大3案**。「ほかの伴奏」で比較する。候補ごとにフレーズ全体のコード進行が変わる。最大3案は提示数であり、進行カタログを3種類に制限しない。
4. 伴奏付きで聴き、「オッケー」で採用する。候補選択や試聴だけで確定しない。

判定は「このメロディーの唯一の正解コード」を特定するものではなく、用意した進行の中からおすすめを選ぶもの。強拍・長い音・終わりの音・前後の流れを評価する。短い経過音や臨時記号を理由に音符を除去・変更しない。具体的な重みや閾値は試聴で詰める。

メロディーの編集中に毎回コードを入れ替えない。変更後に再判定する場合は「伴奏をえらび直す」を明示操作とする。

### 4.3 手動で直す

**2026-10-01 合意（進行と個別変更）**：フレーズ全体のコード進行を選んで大枠を決め、確定後も小節ごとのコードを手直しできる。まずは1小節1コード。小節上部のコードを押して別のコードを選び、試聴して確定する。例：C → Am → F → Gを採用後、3小節目のFだけをDmへ変更できる。進行やコードを変更してもメロディーは変更しない。手動変更した小節は後の自動提案で無断上書きしない。

**2026-10-01 合意（コード種・分数コード）**：小節ごとの個別変更はメジャー／マイナー／7／maj7／m7／sus4／dim／aug／6／m6／add9／m(add9)／m7♭5の13種類に対応し、ベースを別指定する分数コードも選べる。曲末で合意済みの12種類＋分数コードを小節ごとの編集へ共通化し、m7♭5を追加する。m7♭5はルートから[0,3,6,10]半音で、dim=[0,3,6]とは別種。CメジャーのBm7♭5（B・D・F・A）はダイアトニックな7thコードであり、基本的な和声の選択肢として含める。曲末のコード種にも同じ追加を要件・基本設計へ反映済み。

**合意（選択機能）**：まずその調に合うコードを候補ボタンで選んで試聴できる。「ほかのコード」ではルート＋13種類、「ベース」では分数コードを自由指定できる。キー外の指定も拒否しない。最後に「オッケー」で確定する。ベースの通常値はルートと同じで、和音構成音以外も許容する既存合意を継承する。手動指定の小節には目印を付け、再提案で無断上書きしない。ジャンル変更でもコード指定を保持する。全体の進行へ戻す時は対象を示して確認する。

**UI仮採用**：小節のコードを押すと画面下から選択シートを開き、選択小節を見ながら試聴・詳細指定・確定する。発案者の「UIみてから操作性は相談」に従い、配置・表示量・操作性は実際の画面で確認後に決める。選択機能の合意とUIの本採用を区別する。

譜面には選択したコードネーム、調号、メロディーを表示する。調号だけの推定と伴奏の調選択を区別し、長調／短調を調号だけで確定しない。

## 5. 伴奏の品質を詰める仕様

現行の伴奏配列は試聴用データであり、完成品として固定しない。次の項目を同じメロディー・BPM・音量条件で聴き比べる。

| 観点 | 設計する内容 | 確認する聴感 |
|---|---|---|
| 和音の配置 | 和音の転回・音域、前後のコード間の動きを整理 | コードごとに不自然な跳躍や濁りがない |
| ベース | 拍とルートを支える。必要な変化だけを加える | 低音が混み合わず、拍を追いやすい |
| リズム | 四分刻み・裏拍・分散和音を基礎に、ジャンルごとの強弱と休みを付ける | 全拍同じ強さで機械的に鳴るだけにならない |
| 楽器・余韻 | 役割に合う音色、発音の立ち上がり・余韻を比較 | メロディーを隠さず、必要な区切りが聴ける |
| フレーズの終わり・ループ | 単発試聴と繰り返しのつながりを確認 | ループの継ぎ目で音が重なったり拍が抜けたりしない |
| ミックス | メロディーと伴奏の音量を独立して調整 | スマホとPCの両方で旋律と拍を聴き取れる |

4ジャンルは既存合意を維持し、単に音色だけを変更した同じ伴奏にはしない。以下は編曲の出発点であり採用音源の決定ではない。

| ジャンル | 試聴する基本形 |
|---|---|
| どうよう | 少ない音数、はっきりした拍、控えめな和音とベース |
| ポップ | 拍を支えるベース・打楽器、和音の刻み／裏拍 |
| バラード | 余白のある分散和音、持続音、控えめなリズム |
| ロック | はっきりしたリズム、ベースと短い和音の刻み |

伴奏役割の音色変更、音量3段階・ミュート、メロディーの独立した音色／音量は既存要件を継承する。子どもの制作画面では詳細をシートへまとめ、最初からミキサーを全表示しない。

**合意（音色の方向）**：生楽器風とシンセ等の電子音を両方用意し、同じ伴奏で混ぜて使える。ジャンルごとにおすすめの組み合わせを用意する。パートごとの音色は変更可能で、個別指定をジャンル変更で無断リセットせず、曲と一緒に保存する。具体的な音源・編曲・初期音色の採用は比較試聴後に決める。

品質の採用判定は自動テストだけで行わず、発案者の試聴で決める。まず現行版との差が分かる4小節の比較作例を用意し、PC・Pixelで確認する。iPhoneの優先度は現在の指示どおり低くする。

## 6. 未編集判定・自動保存・終了

### 6.1 「作業がある」の境界

| 操作 | 作業の扱い |
|---|---|
| 新規メニューから制作画面を開く | なし。空作品の保存枠を確保しない |
| おためし・既存作品を開くだけ | 新たな変更なし。元データを保持 |
| タブ切替、譜面／カード表示、音符選択、カーソル移動、試聴・ループ練習 | 変更として扱わない |
| 音符・休符の候補を入力、既存音を編集 | 入力中の作業あり。確定前は草稿 |
| 音符がない状態で伴奏・コードを明示的に確定 | 作業あり。コード進行から始めた作品として保存を開始 |
| 調・伴奏・テンポ・音色・保存する音量設定・名前を変更 | 実際に値が変わった時に作業あり |
| 入力用の高さ・長さだけを選択 | 作品データの変更なし。これだけでは未編集のままで保存枠を作らない。コード変更は別判定 |
| 録音ボタンを押して待つ／途中中断 | 予約だけでは作品の変更なし |
| 録音結果を候補として得る／記録を明示的に取り込む | 利用者が作った／取り込んだ作業あり |
| 変更をすべて取消して開始時の内容へ戻す | 未保存変更なし。Undoの保持とは別に判定 |

初期値の自動設定は利用者の変更に数えない。同じ値を選び直した操作、入力エラーだけでモデルが変わらなかった操作は作業を新設しない。入力元を開くために候補が自動生成される場合は、それだけで編集開始としない。

作業中の変更の有無と、新規作品の保存枠を作る条件は区別する。新規の保存開始は6.2節の合意条件に従い、設定値を変更したという理由だけで空作品の保存枠を確保しない。

**合意（未編集判定）**：操作回数や画面を開いたかではなく、音符・コード等の作品データ、または利用者が編集した草稿の内容が変わったかで判断する。高さ・長さの選択だけを未編集とする扱いは、その操作だけに限定し、コード変更へ広げない。入力設定は制作中に覚えておき、作品の保存開始後は内容と一緒に復元できるようにする。

### 6.2 保存の単位と開始時点

最大10曲、端末内保存、1曲にフレーズ・配置・伴奏・テンポ等をまとめる既存合意を維持する。

**2026-10-01 合意（保存開始）**：まず音符の有無を見て、音符がなければ、利用者が伴奏・コードを明示的に確定しているかを見る。「音符がある、または伴奏・コードを明示的に確定した」を新規作品の保存開始条件とする。音符なしでも、コード進行から作り始めた内容を保存し、続きからメロディーを追加できる。初期設定が表示されただけ、候補を試聴しただけでは保存枠を作らない。新規作品の枠を「初めて何らかの設定値を変更した時点」で作る旧提案は、この条件へ置き換える。

保存開始後は同じ曲へ音符・伴奏・設定をまとめて自動保存する。10曲満杯なら保存開始条件を満たす新規入力・伴奏確定や複製の前に一覧からの整理を案内し、自動削除しない。既存作品の編集は可能。

**合意（草稿の保存・復元）**：自動保存は確定版と未確定の草稿を分け、利用者が入力・編集した音符・休符・コード変更・録音結果も草稿として保存する。自動生成した比較候補を眺める・試聴するだけでは制作した草稿を作らない。保存や再読み込みで勝手に確定しない。再開時は未確定の状態で復元し、試聴・修正・オッケーが必要。録音結果は解析した音符を保存し、生音声は保存しない。終了ボタンだけに依存せず制作中から保存し、不慮の停止では最後に保存成功した草稿から復帰する。

**合意（名称とUndo）**：子ども向け画面では草稿を「つくりかけ」と呼ぶ。1手ずつ「もどす」ための操作履歴は同じ制作セッション中だけ保持し、通常の画面切替・試聴では維持、終了・再読込後には復元しない。曲の内容・草稿・原曲・直前版の保存とは分ける。

作品に保存するのは音符・設定と必要な診断メタデータであり、生音声は含めない。採用した伴奏と手動コード指定は再読み込みで同じ演奏結果を再現する。「ととのえる」の原曲・直前版の保存条件は既存Q1と合わせて別途具体化する。

### 6.3 戻る・別メニュー・やめる

- 未編集なら、戻る／別の作り方／やめるで破棄確認を出さない。
- 制作から作り方選択へ戻る時は作業を保持する。別の新規制作へ替える場合も、保存済みの現在曲・つくりかけを無断削除しない。
- **合意（通常終了・再開）**：「やめる」は確定版とつくりかけの保存完了を待って終了し、保存成功時は終了確認を出さない。次回その作品を開いた時につくりかけがあれば「つくりかけがあるよ。どうする？」と確認し、「つづきから つくる」／「つくりかけを けす」を選べる。不慮の停止後も同じ復元操作を使う。
- **合意（つくりかけの削除）**：確定済みの内容がある曲では草稿だけ捨てて確定版へ戻す。一度も確定していない草稿だけの新規曲では作品一覧から取り除き保存枠を空ける。画面は前者で「きめたところは のこるよ」、後者で「このきょくを けすよ」と対象範囲を示す。音符がなくても確定した伴奏・コードがあれば確定版がある曲として扱う。確定版ごとの作品削除は一覧の別操作。
- **合意（保存失敗）**：メモリ内の作業と以前の保存内容を保持し、保存できていない場合だけ終了前に「まだ ほぞんできていないよ」と確認する。「もういちど ほぞん」／「つくるのを つづける」／「ほぞんせず やめる」を選べる。保存成功前に「保存しました」と表示しない。
- 自動保存を実装するまでの試作では、変更した作業の破棄確認と「再読み込みで消える」表示が必要。永続保存の実装済みとは扱わない。

## 7. スマホ画面

制作画面では1小節の譜面／番号カード、現在のコード、入力方法、聴く・録音・停止・オッケーを近くへまとめる。ド〜シは重ならない1段、長さは音符アイコン、休符は別ボタンというv25の操作を利用する。

ハナウタ待機・録音中は入力ボタン群の場所をカウントダウンと進行表示へ替え、上下スクロールしなくても開始と中断が分かるようにする。伴奏の詳細、音色、ミックスは設定シートに置く。

コード選択シートは4.3節の仮採用案。具体的なUIを提示して操作性を相談するまで本採用とは扱わない。

録音中・再生中はタッチで制御する。無音の編集区間では既存の音声操作を利用できる。タッチだけですべての操作が可能。390pxを主確認、320px・横画面・文字拡大で停止や確定への到達を確認する。

## 8. 検証と進め方

### 操作の受入

1. 何も変えずに自由／イメージ／おためしを往復しても、空作品・草稿・破棄確認が増えない。
2. 音・伴奏・名前等を変更すると作業ありになり、未確定草稿を無断で失わない。
3. 同じ伴奏へ譜面入力／ハナウタ入力の両方でメロディーを作れ、録音取消で旧メロディーへ戻れる。
4. ループ中のどこで録音を押しても予定先頭から1フレーズだけ録る。先頭直前押下・二重押下・60／120／180 BPM・4／8小節を確認する。
5. カウントダウンと小節頭が音と合い、遅延補正後に同じ位置へ量子化される。実端末ではイヤホン／スピーカー／Bluetoothを分けて測る。
6. 自動伴奏候補を試聴しても旋律と確定版を変更せず、手動コードが再提案やジャンル変更で失われない。
7. 10曲の保存、再読込、候補復元、保存失敗、2タブの競合、削除後の遅い保存通知を検証する。
8. 譜面・コード表示と再生が対応し、停止・退出・非表示で旧録音や予約音が残らない。
9. 音符なしでも伴奏・コードを明示的に確定した作品を保存・再開し、同じ伴奏へメロディーを追加できる。初期設定の表示・候補試聴だけで空作品を増やさない。
10. 未確定の音符・コード・解析済み録音結果をつくりかけとして復元する。通常終了／不慮の停止後の作品再開時に復元を確認し、草稿だけの新規曲を捨てた場合は枠を空ける。確定した伴奏だけの曲を削除しない。
11. 高さ・長さだけの選択は作品データを変えず、コード変更を未編集扱いへ誤分類しない。終了・再読込後にUndo履歴を復元せず、制作中の画面切替・試聴では保持する。
12. 保存失敗時だけ終了前に3つの復帰操作を表示する。生楽器風／電子音の混合編成、指定音色・各小節コード・ミックスの保存とジャンル変更後の保持を確認する。

既存の画面遷移・編集・録音・再生・連結のブラウザ経路を検証の入口とする。純粋処理は境界時刻、コード候補、保存上限・競合を検査し、画面経路と実声検証を置き換えない。

### 実装の進め方案

1. 合意反映文書を参照し、具体的UIと伴奏比較作例を確認する。2026-10-01に実装指示を受け、ローカル実装・ブラウザ検証を開始した。
2. 未編集判定・保存・再開を接続し、検証フレーズを残せるようにする。
3. 伴奏品質を試聴で調整し、通常入力と記録読込に同じ伴奏設定を接続する。
4. ハナウタのループ再生・録音予約・表示を試作し、端末別に確認する。
5. 基本進行のおすすめと手動の小節別変更を接続する。

伴奏の自然さや回り込みの評価で成立しない点が出た場合は結果を示して仕様を再検討し、黙って機能を省略しない。
