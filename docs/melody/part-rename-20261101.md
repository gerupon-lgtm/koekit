# フレーズの名前変更

## 依頼と操作
利用者が名前の変更方法を質問し、公開版の入力欄が非表示で変更できないことを確認した後、「対応お願いします」と実装を依頼した。従来の質問段階の改善案と、今回の正式な実装依頼を区別する。

「曲全体」→「この曲のパーツ」でフレーズを選ぶ→「名前を変える」→入力→「この名前にする」。完成済み・つくりかけの両方で使える。名前欄は現在の名前を選択して開き、既存と同じ24文字まで。前後の空白を除き、空欄はその場で説明する。日本語変換中の確定で誤って保存しない。入力途中の取消・とじる・Escapeは名前を変えない。

同じ部品を曲内の複数箇所に配置している場合、元の部品名と全配置の表示名をまとめて変える。コピーした別部品や別の曲には反映しない。名前の変更に音符編集の「オッケー」は求めず、この名前にする操作で確定して既存の端末内保存へ接続する。サンプルでは保存枠を使わず同じ操作を試せる。

## データと画面
- `project-session.renamePart` が部品の名前と、登録済みなら対応するパターンの名前だけを変更する。調、コード、空白、音符、配置ID、編集中の候補、カーソル、Undoやコピーの内容を変更しない。未完成の部品を自動で完成・配置しない。
- 未変更は何も書き換えず、空欄や消えた対象は変更せず返す。名前の重複は旧仕様と同様に許容し、新しい制約は加えない。
- 音符の編集中に残した作業内容や、保留した一か所の修正を保護する。名前を変えてから作業の再開・確定・取消・配置Undoをしても旧名へ戻らない。
- 名前変更は部品メニューから開く小さな画面とし、既存の配色・見出し・スクロールする本文・固定の下部操作を再利用する。主制作画面に常設欄を増やさない。文字入力は16px以上、下部操作は44px以上を維持する。
- 名前はHTMLとして解釈せず文字として表示する。従来の非表示欄からの変更処理も同じ名前変更処理へそろえる。

## 2026-11-01 Androidのキーボードに隠れる配置の修正
利用者の実機画像で、名前変更を開いてキーボードが出ると入力欄と確定ボタンが見えないことが判明した。前回の390×450確認は画面全体を縮める条件であり、キーボード上の表示範囲だけが縮む条件の代替にはなっていなかった。この確認条件の不足を訂正する。

[Chrome公式](https://developer.chrome.com/blog/viewport-resize-behavior/)は、Android Chrome 108以降ではキーボード表示時に配置用の領域を変えず、見える領域だけを縮める動作を説明している。[VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)の高さ・幅・表示位置を使い、名前変更画面を見える範囲の上側へ配置する。画面下端固定とsvhだけに依存しない。アプリ全体のviewport指定や他の画面の配置は変更しない。

- 初期表示を入力前に整え、キーボードの開閉・表示位置の移動・回転時のresize/scrollで再配置する。同一フレームの変更は1回にまとめる。
- 入力中の再フォーカス・全選択・ページスクロールは行わない。文字、カーソル、日本語変換状態を保つ。
- 見える高さが短い場合は補足文を折りたたみ、ごく短い場合は重複する上部見出しを省略して、入力欄と下部の確定・取消を優先する。取消は下部から使える。幅が狭いときは下部操作を縦に置く。操作域は44px以上を維持する。
- 閉じた際は予約した描画と位置指定を解除する。VisualViewportがないブラウザーでは画面の高さ・幅とresizeを使う。

`scripts/test-saezuri-rename-viewport-browser.cjs`で、配置用の高さ800pxを維持し、見える範囲だけを420pxへ縮めた状態を作ると、修正前は入力欄625〜673px、確定733〜781pxとなり、ともにキーボード側へ隠れる失敗を再現した。

修正後はChromeとWindows WebKitで、見える高さ420／300／240／190px、表示位置のずれ、狭い表示幅、空欄エラー、フォーカスと文字・日本語変換の保持、ページを勝手にスクロールしないこと、閉じる／再開時の後始末、APIがない場合の代替を確認した。これは表示領域とイベントをモデル化したブラウザー検証であり、Android実機のIME・ブラウザー実装そのものの受入は別確認とする。
