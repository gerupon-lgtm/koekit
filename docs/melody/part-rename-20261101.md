# フレーズの名前変更

## 依頼と操作
利用者が名前の変更方法を質問し、公開版の入力欄が非表示で変更できないことを確認した後、「対応お願いします」と実装を依頼した。従来の質問段階の改善案と、今回の正式な実装依頼を区別する。

「曲全体」→「この曲のパーツ」でフレーズを選ぶ→「名前を変える」→入力→「この名前にする」。完成済み・つくりかけの両方で使える。名前欄は現在の名前を選択して開き、既存と同じ24文字まで。前後の空白を除き、空欄はその場で説明する。日本語変換中の確定で誤って保存しない。入力途中の取消・とじる・Escapeは名前を変えない。

同じ部品を曲内の複数箇所に配置している場合、元の部品名と全配置の表示名をまとめて変える。コピーした別部品や別の曲には反映しない。名前の変更に音符編集の「オッケー」は求めず、この名前にする操作で確定して既存の端末内保存へ接続する。サンプルでは保存枠を使わず同じ操作を試せる。

## データと画面
- `project-session.renamePart` が部品の名前と、登録済みなら対応するパターンの名前だけを変更する。調、コード、空白、音符、配置ID、編集中の候補、カーソル、Undoやコピーの内容を変更しない。未完成の部品を自動で完成・配置しない。
- 未変更は何も書き換えず、空欄や消えた対象は変更せず返す。名前の重複は旧仕様と同様に許容し、新しい制約は加えない。
- 音符の編集中に残した作業内容や、保留した一か所の修正を保護する。名前を変えてから作業の再開・確定・取消・配置Undoをしても旧名へ戻らない。
- 名前変更は部品メニューから開く小さな画面とし、既存の配色・見出し・スクロールする本文・固定の下部操作を再利用する。主制作画面に常設欄を増やさない。文字入力は16px以上、下部操作は44px以上を維持する。
- 名前はHTMLとして解釈せず文字として表示する。従来の非表示欄からの変更処理も同じ名前変更処理へそろえる。

## 確認記録
Nodeの専用4件で、対象のみの名前変更、音と配置・コピーの不変、草稿のままの変更、空欄・不在対象・未変更、24文字、配置Undoと古い作業内容の再取得後の名前保持を確認。

ChromeとWindows WebKitで完成済み／草稿、同じ部品の5配置、コピー・別曲の独立、現在名の選択、空欄、変換中の確定抑止、取消・Escape・Enter、編集中のUndo履歴の保持、元編集の再開とUndo、保留した配置修正の再開・確定・配置Undo、サンプルで保存枠を使わないこと、長い名前・HTML風の文字、保存・再読込を確認。320×568／390×800／393×800／390×450／800×390／1280×800で横溢れがなく下部操作に届く。390×450は高さが減った場合の配置確認であり、Android実機のソフトキーボードの証拠とはしない。

既存の元編集／コピー、固定操作、全体配置38条件、途中再生・点灯維持のChrome回帰も通過。最終Node375件・67ファイルを5ファイル以下の14組で確認し、版整合・差分チェックが通過。新しいキャッシュ値と「この名前にする」の操作名でChrome／WebKitの専用試験も再確認した。公開結果を追記する。
