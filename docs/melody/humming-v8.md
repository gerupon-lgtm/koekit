# ハナウタ試作v8 — ドンカマの同時収録によるタイミング計測

2026-09-27。発案者の「ドンカマも一緒に録って後で除去しタイミングを見る」「是非やってみたい」に対応。共有された同期資料の照合を踏まえた試作。公開先は[試作ページ](https://koekit.sikumilab.com/probe/saezuri/)、公開確認は[公開記録](preview-deployment.md)。

## 目的と変更範囲

v7のPixelは前のめりに歌って期待する再生になった結果であり、自然な歌唱の時刻精度が解決したとは扱わない。v8はスピーカーからマイクへ実際に入った準備カウントで入出力経路の時間差を計測する。音程・長音判定・16分量子化は維持し、BPMに比例した一律前倒しは追加しない。譜面の音価表示・編集、OS音声処理ON時のカウント欠落は別の残課題。

## 操作

「録ったドンカマでタイミングを合わせる（試作）」を既定ONで追加。まずスピーカー、カウント音ON、OS音声処理OFF、追加補正0で自然に拍へ合わせて歌う。準備カウント中は声を出さず、カウント後に4小節歌う。終了後の表示で「ドンカマ実測：…ms」「従来の推定補正」のどちらを使ったか確認し、記録をコピーする。チェックを外せば従来条件との比較ができる。

イヤホンなどでクリックがマイクへ入らない場合は実測不可。Bluetoothの遅延を自動解消できると保証しない。計測範囲は0〜750ms、先頭アクセントの検出が必須。高域を強く落とすマイク・音声処理や反響でも検出できない場合がある。端末別の実測補正を永続保存する機能はまだなく、毎回のカウントで測る。追加ms補正は既存の端末内保存を維持。

## 処理

- `acoustic-sync.js`はDOM非依存の計測・録音区間選択。再生する既知のシェーカーと、録音信号の同じ高域強調処理後の正規化相関を取る。粗探索後に全標本で検証し、相関0.35以上かつ高域RMS0.0003以上を候補とする。閾値は試作値。
- 6発の準備音（beat 0,2,4,5,6,7）を照合。最初のアクセントで0〜750msを探索し、残りはその差±45ms以内。中央値から±12ms以内の4発以上、採用した差の最大最小差12ms以下で成功。雑音や欠落・不安定な結果は推定へ戻す。演奏中の追従補正／クロックドリフト推定は未実装。
- 音源バッファを準備してから350ms先の開始時刻を確定。カウントの100ms前から、曲末の最大1.2秒後までWorkletで端末内収録する（推定補正がそれ以上ならその終端まで）。実測後に4小節の範囲を切り出す。手前のカウントは旋律に含めず、遅延した曲末も保持する。
- 成功時の開始時刻は`musicalStart + measuredDelay + manualMs/1000`。推定遅延に実測を足さず、置き換える。失敗時はv7の推定開始フレームをそのまま使う。量子化前の時間基準を移すので、先頭休符の無条件削除ではない。
- 声の解析側は既存の低域通過フィルターで録音中シェーカーの高域を抑える。反響した波形の完全除去や加工音声の書出しを保証する機能ではない。
- 診断`capture.acousticTiming`に成否／理由、各カウントの予約・検出時刻・相関値、採用数・ばらつき、実測遅延、推定／適用補正、推定との差を16分単位に換算した`adjustmentTicks`、計測時間を追加。`unquantizedNotes`は丸め前の音区間。`timing.captureStartFrame/captureEndFrame`は収録全体、`startFrame/endFrame`は解析に使った4小節。
- 音声はWorker終了とともに破棄し、ファイル保存・外部送信・クリップボードへの波形出力をしない。記録は数値と音符のみ。既存の停止・マイクOFF・候補の2段階確定を維持。

## 検証

ローカルでNode56件、Chromeの録音経路・実測成功／fallbackのUI・通常操作・記録コピー／表示オクターブの各検証と版整合検査が成功。曲末tick64まで続く長音を保持することも確認。公開前レビューで重大な指摘なし。実機の音響経路は未検証。

```powershell
node --test scripts/test-saezuri-acoustic-sync.mjs scripts/test-saezuri-capture-timing.mjs scripts/test-saezuri-boundaries.mjs scripts/test-saezuri-humming.mjs scripts/test-saezuri-sustain.mjs
node scripts/test-saezuri-acoustic-browser.cjs
node scripts/test-saezuri-acoustic-ui-browser.cjs
node scripts/test-saezuri-probe-browser.cjs
node scripts/test-saezuri-report-display-browser.cjs
node scripts/check-version.cjs
```

Nodeでは60/120/180 BPM、44.1/48kHz、173/420msの遅延、声重畳、反響・音色変化・極性反転、クリック欠落／外れ値／不安定／雑音、追加補正とfallbackを検証。Chromeの合成MediaStream→Worklet→Workerでは173msの注入に経路のバッファ遅延が加わり約194msを実測。厳密な173msはNodeの標本列試験で確認し、ブラウザでは先頭8分休符・7音の位置と曲末保持を検証する。ブラウザUI試験はWorkerへの入力だけを合成音へ置換し、実測成功／fallback表示・操作ロック・診断出力を確認する。いずれも実スピーカーと実マイクによる検証ではない。

実声の時刻精度・クリック検出率・Bluetoothの経路・端末別の処理時間は公開後の実機確認対象。声の周期判定自体の境界ずれや耳／マイクへの到達差は、この校正だけで解消したとは扱わない。
