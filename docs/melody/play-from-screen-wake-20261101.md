# 選んだ配置からの連続再生と画面の消灯対策

## 依頼と操作
利用者が2026-11-01に「選択したフレーズ以降を続けて聴く」ことと、PWAが暗くなって再生が止まる現象への対策を依頼した。曲全体の「曲の並び」のカードをタップすると、「このパーツを聴く」に加えて「ここから続けて聴く」を表示する。後者はメニューを閉じ、その配置から後のパーツと「おわりの和音」まで続けて再生する。通常の「並びを聴く」は先頭からのまま。

同じAを複数回使っていても、タップした配置のIDを使って開始する。下の「この曲のパーツ」は曲内の配置位置を持たないため、途中からの開始は上の並びのカードで選ぶ。音楽データや配置を削除・並べ替えず、試聴用のデータだけを切り出す。

## 再生の設計
- `sequencePlayback` の任意引数に配置IDを指定できる。従来の引数なしの戻り値は変えない。
- 元の構成を検証してから開始配置を特定し、それ以降のメロディー・伴奏・空白・長さと終止和音を共通処理で組み立てる。開始位置がなければ明示的なエラーを返す。
- 音声の時刻は切り出した先頭を0にする。元の曲での開始位置を別に返し、画面の小節表示・配置の強調表示には元の位置を使う。
- メニューを閉じる既存処理が新しい再生を止めないよう、closeイベントの既存の停止処理を終えた後に新しい再生を開始する。
- 途中再生後の全体再生や停止で開始位置をリセットする。曲の内容と保存データ、候補確定・Undoは変更しない。

## 画面の点灯維持
標準のScreen Wake Lock API（画面が自動で消えるのを防ぐ機能）を利用する。準備・再生・録音・解析中と独立したドンカマの再生中だけ取得し、停止・自然終了・エラー・画面を閉じた際に解除する。操作を強制する新しい設定は追加しない。端末への外部送信や動画の偽再生は使わない。

- 要求は同じ活動中に1回とし、毎回の描画・音声予約では要求しない。
- 停止してから遅れて許可された場合はすぐ解除する。停止→再開始の途中に古い許可が返っても、新しい再生には新しい取得を行う。
- 非表示では解除し、表示へ戻った際は活動中の場合だけ再取得する。OSによる拒否・取消を無限に再試行しない。
- 機能がない／拒否された場合も音声再生は継続できる。右上設定の端末欄に現在の状態と、必要な場合の端末の消灯時間設定の案内を表示する。診断にも状態を残す。
- 既存の「画面が隠れたら停止する」動作は維持する。今回の対策は再生中の自動消灯の抑制であり、手動ロックや他アプリへの切替後のバックグラウンド再生を追加する依頼とは分ける。

[MDNの仕様説明](https://developer.mozilla.org/en-US/docs/Web/API/WakeLock/request)では、HTTPSかつ表示中の画面で利用する。電池残量・端末設定によって拒否・取消され得る。[WebKit公式](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)はiOS／iPadOS 18.4でホーム画面のWebアプリにも対応したと説明している。利用者の端末・OSは質問中で、物理端末の自動消灯と聴感をPCのAPI検証で完了扱いにしない。

## 確認記録
ローカルの純粋処理6件が通過。繰り返しAの2回目からのメロディー／伴奏と表示位置、最後と終止和音、空白を保つ長さ、元データ不変を確認。画面点灯維持は重複要求なし、停止・自然終了相当・画面終了、遅延許可と再開始、非表示／復帰、OS取消、未対応・拒否と無限再試行なしを確認した。

Chromeで実際のWeb Audio再生・ネイティブの点灯維持要求と解除、繰り返し配置から最後までのカード追従と自然終了、全体再生への復帰、4サイズ、保存データ不変が通過。未対応／拒否／許可の注入では、再生を保つこと、設定の表示、閉じても再生を保つこと、停止解除、独立ドンカマ、非表示時の既存停止と解除を確認。WebKitは配置メニューの4サイズと保存データ不変を確認し、音声APIがないため音声・消灯防止の実機証拠とはしない。
