# ハナウタ試作v9 — マイク開始後の待機延長

2026-09-27。Windows 11でカウントの1小節目が欠落する場合があり、発案者はマイクONのタイミングとの関連を指摘し、録音開始指示後の待機延長を提案した。OSの経路切替が原因という点は未確定。今回の変更で実機再検証する。

- マイク許可・入力ノード接続・シェーカー音源準備を終えてから、最初のカウントまでの猶予を350ms→2秒に変更。
- 画面に「マイクの準備待ち・カウントまで○秒」を表示。準備待ち中も停止・マイクOFFで予約と入力を解放できる。
- カウントと録音の基準時刻を一緒に後ろへ動かす。2分×2→4分×4の8拍、録音4小節、v8の実測／推定補正・音程判定は変更しない。2秒を音符の補正値へ加算しない。
- 記録は`ML-T01-v9`。`capture.timing.preparedAudioTime`と`startLeadSeconds`（2）を追加し、準備後の音声時計とカウント開始までの猶予を確認できる。

検証は既存の通常操作ブラウザ試験（待機表示中のマイクOFF取消を含む）と、実測成功／未検出fallbackの録音経路試験（先頭休符・7音・曲末保持）、版整合検査。Windows／Pixelでのカウント欠落の解消は、公開後の実機再確認対象。

v8実機結果は[humming-v8.md](humming-v8.md)。公開URLは[試作ページ](https://koekit.sikumilab.com/probe/saezuri/)、公開検証は[公開記録](preview-deployment.md)。
