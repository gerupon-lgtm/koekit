# ハナウタ試作v12 — 同じ入力で音程の区切り方を比較

2026-09-27。識別子は`ML-T01-v12`。v11 Windowsの実声で、長音は1音を保持したが、声を切らないG／G♯の8分交替が6音へまとまった。従来の記録には検出後・ならす前の音高推移がなく、検出器と音符化の寄与を分離できなかった。再歌唱による入力差を避け、1回の取り込みから比較できる診断を追加する。

## 操作

1. 検証ページを再読み込みし、「今回の比較設定にする」を押す。
2. Windowsのこれまでと同じスピーカー・マイクで「カウントして取り込む」を押す。
3. カウント中は声を出さず、録音開始から声を切らずにG／G♯を8分音符で交互に4小節歌う。
4. 完了後、「記録をコピー」の内容を共有する。記録の`prototype`が`ML-T01-v12`であることを確認する。

設定ボタンは120 BPM・長音・ならし120ms・4096標本・短区間の無音判定・短窓補助ON・補完上限0.10秒・RMS0.008・検出率下限0.5・追加補正0・OS処理OFF・実測／準備／録音カウントONにする。カウント音量は直前の選択を保つ。設定は次の取り込みに使い、以前の候補を書き換えない。録音・解析・再生中は変更不可。

## 比較する段階

実測同期・カウント帯域抑制・音高検出を1回行った後、その**同じ音高フレーム**を以下の3条件で音符へ変換する。音声波形の解析を3回行うものではない。

| 記録のmode | 比較条件 |
|---|---|
| `current` | 録音時の設定による通常結果。現在の候補・試聴・採用はこれを使用 |
| `detail` | 音の区切りを「細かい変化」へ変更し、ならし時間は録音時の設定を使用 |
| `unsmoothed` | 音高のならしを0msにして比較。量子化と同音不明区間の補完条件は共通 |

「ならしなし」は無加工の音声や正解の音符列ではない。音高検出、短窓補助、同音補完、最近傍半音・16分化は経由する。別条件の結果を自動採用せず、3つの音数は正解率として扱わない。

## 記録

- `capture.analysisComparison`：同じ検出フレームを使った3方式の音符数・量子化前区間数・音列・補完と補正履歴。音列は`noteColumns`に沿う数値の組。
- `capture.analysisComparison.pitchTrace`：音高検出後、ならし前の時刻・音高・音量・確信度・検出種別等。`columns`に沿う配列をJSON Lines文字列で保持する。数値は丸めず、同じ音高フレームから再解析するための精度を保つ。
- `capture.comparisonMs`：上記比較と記録生成に使った追加時間。`analysisMs`にはこれも含む。

`analysis-comparison.js`の`decodePitchTrace`で復元し、`analyzeFrames`へ入力できる。生波形・端末識別子は含めない。通常の解析と同じく波形はWorker終了時に破棄し、音声ファイル保存や自動外部送信は追加しない。記録のコピーは利用者の操作で行う。

録音開始時に以前の`playback`欄をクリアする。前の取り込みの試聴を今回の結果と読み違える問題を避けるためであり、再生ロジックを変えるものではない。

## 今回の範囲と次の調整

v11の音高・区切り・補完・時間量子化の閾値を維持した診断更新。切らない半音交替の精度改善が完了した版ではない。

新しい1回の入力で、ならす前にはG／G♯の動きがあるのか、細かい変化では保持できるのか、長音設定でどの時刻がまとまるのかを確認する。そこで得たフレームを使って調整案を再実行し、長音の回帰条件と併せて検証する。v11以前のJSONにはこの推移がないので、過去の歌唱から復元できたとは扱わない。元の音高検出窓やRMS判定を変えた再検出には波形が必要であり、今回の数値記録だけでは再実行できない。
