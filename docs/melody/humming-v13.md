# ハナウタ試作v13 — 取り込み候補を選んで編集

2026-09-27。識別子は`ML-T01-v13`。取り込み候補の後編集を実装。配信状態は[公開記録](preview-deployment.md)を参照。本アプリの完成・Q1〜Q3の合意とは分ける。

## 方針

[v12のWindows実声](humming-v12.md)は同じ375フレームから長音7音／細かい変化19音／ならしなし33音を再現した。検出後の音高にはG／G♯の交替が残り、ならし・境界判定による統合が主な差と確認できた。一方、短い半音交替を拾う閾値の緩和には長音の誤分割との両立が残る。ならしなしの33音にも時刻ずれと末尾音があり、正解の音列とは扱わない。

発案者の「音程は譜面上で編集できればOK」「後続の処理で吸収できるならその方針で大丈夫。自動だと難しそう」を受け、自動調整の探索を区切り、候補を手直しする工程へ進む。v12の検出・ならし・境界・補完・量子化の条件は維持し、期待する32音や拍位置へ自動で合わせない。

## 試作で使える操作

1. 取り込み結果の「現在の設定」「細かい変化」「ならしなし」から編集の元を選ぶ。同じ検出フレームの比較であり、歌い直しは不要。方式ごとに編集状態を保持する。
2. 譜面の音符をタッチするか、音符一覧から選ぶ。小節をまたぐタイの表示も元の1音符を選ぶ。
3. 音高・開始位置・長さを指定して置換する。または指定位置で分割、次の隣接音と結合、削除を選ぶ。開始・長さは16分音符単位。
4. 未確定の編集候補を譜面と試聴で確認し、確定または取消する。選択や試聴だけで確定しない。確定後は「もどす」で直前の編集を戻す。

分割は音符の内部だけを許可し、左右に元と同じ音高を持たせる。結合は時刻順で次の音符が隙間なく接する場合だけ許可し、休符を埋めない。重なり・小数tick・4小節末尾超過・無効な音高は候補として拒否する。元音域をC4〜C6へ強制的に制限しない。編集結果の音高変更と、調号・表示オクターブだけの変更は区別する。

編集は取り込み候補の内部で行い、元の解析結果・3方式の診断記録・既存作品を上書きしない。方式の切替で別方式の編集を移し替えない。古い状態から作った候補や二重確定は拒否する。方式ごとの状態保持は今回の画面内の編集であり、再読込後の永続保存を意味しない。

## 既存の数値記録を使う

「過去の記録から元の取り込みを開く」に診断JSONを貼り付け、「記録を読み込む」で候補を再開する。v12以降の`analysisComparison.pitchTrace`があれば同じ検出フレームの3方式を利用できる。それ以前は元の音符だけを開き、3方式比較は無効にする。記録の音符・テンポ・比較条件・推移の数値と順序を検証し、不正な入力は現在の候補を変えずに拒否する。読み込みは現在の取り込み候補を置き換える。以前の手編集履歴や`captureCandidate`を復元するものではない。

今回のWindows v12記録では375フレームを復元し、元の7音と19音／33音の比較を再現できた。追加録音は不要。「ならしなし」から余分な末尾音を削除し、開始位置や区切りを手直しする使い方を評価する。

診断の`capture`は元解析、`captureCandidate`は現在の確定済み作業候補、`captureEditing`は選択方式・選択音・revision・未確定候補を表す。採用後も編集済み作業候補を記録に残す。貼付読込元の版・日時・所感は`importedFrom`へ保持し、新規録音時に消去する。頭合わせは手編集前だけ利用でき、方式ごとに保持する。

対象は音符・音高フレーム等の数値記録。生波形の保存・読込・外部送信は追加しない。曲の端末内保存（ML-012）や本アプリの作品読込とは別の試作用途。

## 実装と検証の状態

候補作成は既存`saezuri/document.js`の検証・確定・undoを再利用する。試作用`capture-editor.js`は置換・削除・分割・隣接結合を候補化し、UIは`capture-editor-view.js`で取り込み表示へ接続する。既存モデルを作り直さない。

Node41件（編集・文書モデル・同一入力比較・記録読込）が成功。別エージェントのコード確認と、実際のv12記録の再計算も一致。以下はChromeの結合検証で確認した。

- 未確定の置換・削除・分割・結合で元の音列が変わらず、確定／取消／undoが期待する音列・選択へ戻る。
- 重なり・末尾超過・休符をまたぐ結合・古い候補・二重確定を拒否する。タイ表示から正しい元音符を選べる。
- 3方式を切り替えて編集を保持し、試聴・譜面・記録が現在の候補と一致する。解析元の診断は保つ。
- 数値JSONの読込、非対応・不正な入力、録音／解析／再生中の操作、停止・取消を確認する。
- 通常操作・捕捉、ドンカマ実測成功／推定fallback、コピーと表示オクターブの既存検証も成功。新規編集試験は実捕捉のあと固定音高フレームを与え、実際の解析関数から比較候補を作る。実声の検出精度を示す試験ではない。
