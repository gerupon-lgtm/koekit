# Pixel 6aの瞬間的な音欠け（2026-10-18）

## 報告と確認できたこと

Pixel 6a／Chromeで、制作して保存した曲の再生に一瞬の歪み。動画の19秒付近と指定があり、録画をしない再生でも別の位置に途切れが出たと本人から報告された。別の2オペFM音源でも似た症状がある。これだけで、端末負荷・ブラウザー・音源のいずれかへ原因を確定しない。

提供動画から抽出した48kHzの音声は約8秒のフレーズが2回ある。19.44225〜19.44483秒に約2.58msのほぼ無音の区間があり、8秒前の対応箇所にはない。2ms区間の実効振幅は対応箇所の約0.0084倍。波形の上下が潰れる形ではない。48kHzの標準128サンプル処理は約2.67msで、長さは近いが、それを原因の確証とは扱わない。動画・抽出音声・本人の曲は公開ファイルへ追加していない。

提供記録は120 BPM・8小節・旋律28音・伴奏176イベント・カウント32発・`light`／`piano`・全体200%。`scheduleMode: phrase`、`reason: ENDED`で先読み不足による停止記録はない。タイマー最大36.8ms、画面最大19.4ms。`baseLatency`は約2.67ms、`outputLatency`は21ms。最大264発振器は将来の事前予約と余韻を含む所有数であり、同時に聞こえる音数ではない。

## 今回の対応

- 通常は従来と同じ `interactive`。比較用の `?audioLatency=playback` だけ、`AudioContext`の遅延要求を `playback` にする。音色・音符・音量・減衰・先読み方式を変えず、音符の事前合成や発音数の削減は行わない。URL設定は曲や端末設定へ保存しない。
- ブラウザーの `playbackStats` に対応する場合、各再生の開始前後の差を `playback.audioOutputStats` に記録。`underrunEvents`は出力不足の報告回数、`underrunDuration`と`totalDuration`の単位は秒。以前の再生の累積回数を加算しない。
- 未対応・読み取り失敗は `status: unavailable`、累積値の巻戻りは `counter-reset`。測れない場合を0回と扱わない。測定0回もブラウザーが検出した範囲の値であり、すべての聴感上の欠けがなかった証明にはしない。
- 音の統計は再生開始／停止と検証記録の表示時だけ読む。描画の各フレームや、音を合成する処理に監視を追加しない。自然終了・停止・途中の記録表示に対応。
- 既存の「設定」→「録音・解析・入力の詳細検証」内の記録へ `audioLatencyHint` を追加。曲・保存・鍵盤・ハナウタの仕様を変えない。比較URLでは鍵盤の応答が遅れる可能性があるため、まず曲の試聴に使う。

この指定はブラウザーへの希望値で、実際の余裕は端末の判断となる。実測の `baseLatency`／`outputLatency` と聞こえ方を併せて比較する。通常設定への本採用は未決定。

## PCでの検証と実機の残件

新規Node3件（既定／比較URL、未対応・例外と値のコピー、再生単位の差と巻戻り）と既存の音源・キャッシュを合わせた6件が成功。新規ブラウザー検証は保存曲の自然終了と手動停止、2回の再生での差分、未対応の例外、毎フレームで読まないこと、保存内容の不変を確認する。注入した出力不足の数値で診断経路の正しさを確認する試験であり、Pixelの症状再現とは分ける。

既存のループ録音の回帰も成功。録音予約と取消、マイクOFFによる停止、8小節の取り込みと確定待ち、元の旋律／生成した伴奏の保持を確認した。試験の操作は共通の表示切替補助を使い、カード入力から鍵盤を表示して実際のループボタンを押す手順へ追従させた。

提供された28音の開始・長さ・音程と8小節の伴奏、全体200%を、PC Chromeで非公開の検証データとして再現。両設定で全28音・伴奏176イベントが予約され自然終了し、全28音の出だしに実際の音声出力があった。曲の途中に700msの画面処理停止も入れた。PCでは出力不足の報告は両方0回で、今回の症状は再現していない。通常の `baseLatency` は10ms、比較は20msとなった。PC確認時点の実機の残件と、下記の本人報告を分けて扱う。

Pixelでは、同じ曲と同じ音量で通常URLと比較URLをそれぞれ複数回聴き、途切れの有無と各再生直後の記録を比べる。録画は任意。音源自体の減衰・発音数を先に変えて原因を混在させない。

## 公開後のPixel本人確認

公開 `7c9757747c7d10f9f630cbdf66abc50209794629`、Pages39114897249の全ジョブ成功。公開98ファイルのHTTPS・種類・長さ・SHA-256一致と、公開PC Chromeで提供曲の通常／比較設定、28音・伴奏176イベント、自然終了、各音の出だしを確認した。

続いて提供された `timestamp: 2026-10-18T09:28:07.986Z` の1再生分の記録は、同じ28音・伴奏・全体200%の `audioLatencyHint: playback`。`baseLatency: 0.0213333`、`outputLatency: 0.267`、出力不足1回・合計約21.4ms・計測約17.169秒、`reason: ENDED`。本人の評価は「途切れなし」。通常設定の約2.67msから内部処理の遅延が増えた条件で、聴感上良好な結果を1件受領した。

統計は予約直前から終了までの差で、先頭の無音待ちと末尾の余韻も範囲に入る。出力不足1回の発生時刻は記録していないため、曲の途中に21.4msの音切れがあったとは断定しない。原因の確定、複数回の再現性、iPhone XR、鍵盤・ループ録音への影響、通常設定への採用判断は引き続き未完了。

他アプリへ共有したいとの依頼に基づき、実測・組み込みコード・入力用途との違い・未確認範囲を[他アプリ向け共有資料](web-audio-playback-sharing-20261018.md)へまとめた。今回の追記は資料のみで、通常URLや音源・録音の処理は変更していない。
