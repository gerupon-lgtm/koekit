# 設定の役割分担・毎拍アクセント・数値入力

## 合意と範囲
2026-11-01、画面案08を利用者が承認。通常の操作画面で音楽の内容を編集し、伴奏の設定ではそのパーツの鳴らし方、右上の設定では曲共通と端末の調整を行う。配色・文字・既存操作を共用し、縦スクロールと不要な表示位置の変化を重点確認する。画面案の簡易音・表示の成功を、本番の音声・実機受入とは扱わない。

| 場所 | 項目と責務 | 変更の決め方 |
|---|---|---|
| 通常のパーツ編集 | メロディー、コード・空白、調、小節数、移調、長さ・コピーなど。伴奏タブに実際のコード列と「コードの並びを変える」を置く | 既存の候補・オッケー・もどす |
| 伴奏の鳴らし方 | パーツごとの伴奏ON/OFF、和音の弾き方、打楽器の刻み・アクセント、パートの音色 | 候補を通常画面のオッケーで決める。上下のとじるは同じ動作 |
| 右上の設定 | 「この曲に共通」＝テンポ・メロディー音色。「この端末」＝全体/伴奏/ドンカマ音量、ドンカマの音色とON/OFF、表示・録音調整 | 既存の曲保存／端末設定の保存先を維持。音量は再生中にも変更できる |
| 通常画面の「伴奏を作り直す」 | 既存のジャンル選び直し、イメージによる作り直し、手直しの明示解除 | 選択・試聴と「つかう」を分離。手直し解除は対象を説明してから候補化 |

「伴奏といっしょに聴く」は「伴奏を鳴らす」へ変更。コード・ベース・打楽器全体のON/OFFであり、コードや刻みの設定自体は消さない。進行選択とBPM案は鳴らし方から分離する。既存のジャンル直接選択も通常画面の作り直し内に保ち、選ぶだけでは適用せず「このジャンルをつかう」で候補にする。他の鳴らし方を変えても、未採用ジャンルを取り込まない。

最初のイメージ選択中は細かな伴奏変更を隠し、選択・試聴・オッケーを優先する。確定後の3タブは常に使え、調と小節数は通常画面で変えられる。確定直後に鍵盤へ自動スクロールせず、画面の見出しを保つ。任意の「伴奏を作り直す」は試聴・確定より後に置く。メロディーが空の伴奏だけのパーツでも、音を直すタブからまとめて編集へ入れる。録音中は従来の専用表示で鍵盤・拍・停止を優先する。

## コードの並びと作り直し
コードの変更画面には現在の実際の並び、別案の実際の並び、変わる小節を表示する。手で指定したコード・空白を残すため、単なるテンプレート名で実際の内容を代用しない。選ぶ・聴く・閉じるだけではエディター、保存、Undoを変えない。「この並びをつかう」で候補化し、通常画面のオッケーで確定する。既存の伴奏OFFはコード変更だけでは解除しない。まだ伴奏設定のないパーツへの最初の追加は、候補とともに伴奏を有効にする。

イメージからの作り直しもエディターから分離したローカル候補を持つ。条件変更と「別のパターン」はローカル候補を更新し、次回生成には直前の候補番号を引き継ぐ。取消・閉じる・別パーツへの移動でローカル候補を破棄する。つかう時は元パーツが変わっていないか確認する。手動コード・空白・明示した音色や刻み、メロディー、調、小節、曲のテンポを保つ。

「手直しを外しておまかせ」はコード・空白・鳴らし方の解除範囲を説明する。イメージのタイプ・はやさ・ふんいきは保ち、メロディーを残す。もどすで取り消せる。作り直し中の音声は専用の語彙に限定し、イメージ条件・別案・聴く・つかう・停止・閉じるだけを扱う。通常の音符編集やオッケーへ流さない。

試聴画面の停止は下部に置き、短い画面でもスクロールせず到達できるようにする。鳴らし方と右上設定の下部は、とじるを維持する。

## 毎拍の頭のアクセント
利用者が「1拍＝四分音符」「1・2・3・4拍目の最初の音を毎拍強くする」を確認・承認。8分・16分刻みのアクセントに「毎拍の頭を強く」を追加する。保存値は `drumAccent: beats-1234`。強い音 .06／弱い音 .008 を保ち、0/4/8/12 tickだけを強くする。全音が均等になる二分・四分刻みにはこの選択を追加しない。旧ハットや他のアクセント、コード境界での拍の固定、コピー・保存・再生成は維持する。

## 数値の直接入力
利用者の指定と、関連スキル資料 `requirements-definition/references/ui-input-and-brand-standards.md` の遅延全選択ルールを今回の数値欄へ適用する。基本設計スキルは増分モードで使い、日時入力用の区切り補完やピッカーは今回追加しない。

- 未フォーカスの数値欄へ入ったとき、50ms後に `input.select()` で現在値を選び、数字で置き換えられるようにする。
- 同じ欄の再タップでは全選択を強制せず、カーソルによる部分修正を保つ。clickによる再選択は追加しない。
- 入力欄ごとの予約を、blur／入力開始／IME変換開始／キー操作／ダイアログ終了／画面離脱で解除する。実行時にもフォーカス・DOM接続・表示・値の一致・disabled/readonlyを確認する。
- 動的に作られるコード画面のテンポにも同じ処理を適用する。数値欄以外の曲名やコピー欄の既存選択は維持する。
- type=number と min/max/step/required、既存の妥当性検証を保つ。50msより早く入力を始めた場合は予約を解除し、後から入力を選択し直さない。
- Androidの編集メニューを抑止する保証はしない。長押し・コピー・貼り付けやタッチ操作を禁止しない。実機のOS・ブラウザー・キーボード・PWAと通常ブラウザーでの受入は、PCのタッチ検証とは区別する。
