# スマホの通常制作画面と8ビート伴奏

## 今回の依頼と範囲
2026-11-01、添付のスマホサイズで通常制作を一画面に収めること、音楽タイプごとに8ビートの伴奏セットを数種類用意することを利用者が指定した。各タイプに基本・軽め・動きのある3種類、計12セットとする。既存の配色、タッチ操作、候補→オッケー、端末内の音声処理、素のES Modulesを維持する。

## 通常画面
- イメージから作ったパーツも、手入力と同じ3タブの構成にする。旧イメージ専用の鍵盤下の編集欄と、共通レイアウトの二重管理を解消する。
- 音を置く：鍵盤／カード入力。音を直す：譜面と選択・移動・削除・高さ・音の位置。伴奏：実際のコード列とコード変更・鳴らし方。
- 編集・伴奏タブの鍵盤は「鍵盤で れんしゅう・録音」から開く。必要な操作を廃止せず、初期表示の重複を減らす。入力・声は調／小節数の横から開く。タブ・パーツを替えたら任意の欄を閉じる。
- 380〜649pxでは音の編集ボタンを2行に配置。文字14px、操作域48px以上を保ち、「たかく」「ひくく」は単語の途中で折り返さない。
- 小節内の譜面の縦枠は112px。待機時の録音ガイドの重複を抑え、再生・録音中は必要な案内を表示する。
- 通常画面の目標は390／393×800 CSS px。390×740も確認対象。320×568・横向き・PC・拡大・任意の詳細操作も検証し、狭い高さでは必要な縦スクロールを許容する。端末のブラウザー上部・文字拡大・実際の操作感は別確認とする。
- 共通の聴く／オッケー／もどすをカード入力に移した場合も、入力部品側で一括して無効にしない。調や長さを変更した候補を確定できることを維持する。

## 8ビートの選択
入口は伴奏タブ→「伴奏を作り直す」→「8ビートから選ぶ」。通常画面の高さを増やさず、タイプとパターンを選べる。候補と現在を聴き比べ、明示的に「この伴奏をつかう」→通常画面の「オッケー」で確定する。選択・試聴・閉じるでは編集内容や履歴を変更しない。もどすと保存・再開も既存処理を使う。

| 音楽タイプ | 基本 | 軽め | 動きのある |
|---|---|---|---|
| どうよう | 4分コード・2分ベース | 2分コード・ベース、弱め | コードを分けて弾き、ベースに動き |
| ポップス | 前後の拍を混ぜたコード・8分ベース | 2分コード・ベース、弱め | コードとベースの位置に変化 |
| ロック | 8分の2音コードとベース | 4分の2音コードとベース、弱め | 休む位置のあるコードとベース |
| バラード | 8分の分散コード | 長いコード・2分ベース、弱め | 分けたコードとベースに動き |

- 全セットでハットを均等な8分音符、スネアを2・4拍目に鳴らす。キックと強さはセット別。既存のハットのみ・アクセント選択とは別の、コード・ベース・ドラムを含むセットである。
- ハーモニーを決める既存のイメージの進行レシピを保持する。進行IDだけに置き換えず、実際に鳴るコード、手指定、スラッシュベース、空白、音符、調、小節数、曲のテンポを保つ。
- 新しい鳴らし方はジャンルと3つのrhythm IDで保存。従来データの移行を追加しない。イメージ再生成でも明示選択した鳴らし方を維持する。
- コード・ベースは小節頭を基準に刻み、途中でコードが変わると即座に新コードを鳴らし、前の音をその境界で終える。ドラムの8分格子はコード境界でリセットしない。
- 空白はコード・ベースを休ませ、ドラムを継続する。セット採用時は伴奏ON・ドラムおまかせにする。ドラムなしを選んでいた場合もセットのキットへ戻す。その後にハットのみ／打楽器なしを選び直せる。手指定のコード・ベース音色は保持する。
- 既存6リズムの再生は変えない。追加前HEADと192条件のイベントを比較し、一致した。再発検出の固定ハッシュも保存する。
