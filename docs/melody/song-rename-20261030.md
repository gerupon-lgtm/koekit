# 保存した曲の名前変更 — 2026-10-30

## 指定と操作

「保存した曲の名前を変更したい」という指定に対応する。従来の制作画面の「設定」内の曲名入力はそのまま残し、保存一覧にも入口を追加する。

「ほぞんした きょく」→曲名の横の「名前」→新しい名前を入力→「この名前にする」。前後の空白を除き、24文字まで。同名も使える。空欄は入力を促して保存せず、取消・とじるでも変更しない。同じ名前なら保存日時・世代を進めない。

一覧は元の3列を使い、曲名を2列、その右に「名前」を置く。下の「聴く・コピー・けす」は元の1行を維持する。名前入力は既存の色調、中央見出し、右上のとじる、44px以上のボタンと8px以上の間隔を使う。

## 保存の扱い

`SongStore.rename` は最新の曲を読み、名前と更新日時／世代だけを変更する。確定済みの曲、つくりかけ、フレーズ、配置候補、音色やテンポなどは保持する。保存上限まで曲があっても既存曲の改名は可能。別の画面による変更・削除、未知の保存形式は上書きせず、失敗時は入力した名前を残す。

編集中の曲は先に通常保存を完了し、改名中は自動保存を一時停止する。成功時に曲名と保存世代を同期し、その後の編集も通常保存する。別の曲の改名のために現在の編集画面を読み直さない。一覧を再取得するため、直後のコピー・削除も新しい保存世代を使う。

## 検証

新規Chrome／WebKit試験で、名前だけの保存、満杯時の更新、同名の無変更、空欄、同時更新の片方だけ成功、削除済み／未知形式の拒否を確認。UIでは編集中の音符候補・配置候補の保持、別曲の改名、取消、競合、保存失敗と再試行、改名後の次の編集保存、コピー・再読み込み、320／390pxのボタン寸法・間隔・見出し中央を確認した。

別担当の読み取りレビューで「今の曲の保存失敗が別曲の改名も止める」点を発見した。新規試験で再現し、同じ曲を改名するときだけ保存完了を必須にして修正。別曲の改名成功と現在曲の保存データ／手元のテンポ・名前保持がChromeで成功し、再レビューのP1／P2指摘はない。

実機の文字入力・ソフトキーボードの使用感は未確認。公開結果は検証後に追記する。
