# ハナウタ v18：編集検証に絞った標準表示

2026-09-27。発案者の「編集モードの検証に特化し、音色・ドンカマの遠さを解消して不要な部分を隠したい」という指定に対応。別アプリを増やさず、同じ試作ページの標準表示を編集中心にした。

## 操作

- ページを開くと作例の編集を開始する。初回の録音をしなくても操作を試せる。
- 同じ編集カード内にBPM、音色、試聴ドンカマ、音量、声操作、マイク、全体±1オクターブを配置。
- 音符選択・上下・削除と同じ操作欄に「聴く」「オッケー」「もどす」、確定・仮変更の状態をまとめた。
- 番号ブロックとスクロールできる五線譜を表示。選択音に追従する既存動作を維持。
- 上部の「音列を開く・ハナウタを録る」から診断JSONの読込や録音を行う。取り込み後は閉じて編集へ移る。録音中は進行が見えるよう開く。マイクOFFと停止は引き続き利用可能。
- 仮の変更が残っている間は別の録音・記録へ切り替えられない。確定または仮変更の取消後に切り替え可能。切替は新しい編集セッションとなり、前セッションのUndoは引き継がない。
- 調号、表示オクターブ、±半音の全体移調、比較方式、数値での編集は「全体の高さ・譜面表示・詳しい編集」に残す。
- 録音・解析の詳細設定、元の入力モデル、測定記録は末尾の「録音・解析・入力の詳細検証」に折りたたむ。
- 編集終了・仮変更取消・記録コピーは譜面の下。コピー失敗時の手動コピー欄は詳細検証を開かず利用できる。

`editor-layout.js`は既存のDOM要素を移動するだけで、音声入力・解析・再生・編集モデルを複製しない。旧技術配置は`?view=full`で比較できる。表示の切替リンクは、編集中の状態をページ遷移で失わせないため通常UIには置かない。

## 検証

- Chromeの新表示：初期作例、記録読込、仮変更中の入力切替禁止、音色・ドンカマを反映した仮試聴、再生中ロック、確定・確定後Undo、移調、音声オッケー、表示8va、終了・再編集、録音進行とマイク表示を確認。
- 320×568／390×844／844×390／1280×800で横方向にはみ出さず、選択した音符が見えることを確認。スマホ実機での使い勝手は次の検証対象。
- 旧技術配置での音声区間・番号移動、録音から3方式の編集、仮試聴・確定・Undo、録音中断のブラウザ回帰も成功。

ここから必要な操作を絞り、スマホ向けの配置を検討する段階。本アプリの完成UI・音声認識精度の合格とは扱わない。
