# 音声入力のソース照合と修正（2026-09-26）

## 確認した既存実装

| 参照元 | 確認内容と今回の対応 |
|---|---|
| `src/speech/vocabulary.js` | ピタリズムの方向語は「右」「みぎ」等の単独語。完全一致・区間外無視を維持する。 |
| `irodori/vocabulary.js` | 数字・方向を辞書にある読みで文法へ渡し、認識後の空白区切りトークンを解析する。「みぎ2」を辞書の1語として渡す方式ではない。 |
| `jintori/commands.js` | イロドリの実測済み読みを参照し、選択とオッケーを分離。Deliveryでも方向のみの選択と、方向＋歩数の指示追加、実行確定を分離する。 |
| `jintori/voice.js` / `irodori/phase.js` | 区間ごとに認識を開閉し、世代番号で停止後のイベントを無効化。Deliveryの同等処理を照合し、共通層・他アプリは変更しない。 |
| `src/speech/vosk.js` / `switchable.js` | 文法はそのままKaldiRecognizerへ渡される。マイクON/OFF、AudioWorklet、確定resultの配送を実アダプタで検証。 |

## 原因

旧 `delivery/commands.js` は「みぎ1」「うえ2」「2ばん」などを連結して文法へ渡していた。Voskは空白で文法の単語を区切るため、日本語モデルの辞書にない連結語が除外される。3行を想定した旧文法では129候補中123候補が辞書不一致だった。ピタリズムの単独方向語は辞書に存在する。

手元の `model.tar.gz` 内 `model/graph/words.txt` と照合し、Vosk本体の [UpdateGrammarFst](https://github.com/alphacep/vosk-api/blob/master/src/recognizer.cc) の単語検索処理とも一致を確認。

## 修正

- 文法を「右 二」「二 番」のように、モデルの辞書にある単語へ分割。数字の算用数字を文法に直接渡さない。認識結果の空白を正規化して既存の指示解析へ渡す。
- 方向だけなら方向ボタンを選択色にし、受信案内を表示する。指示表への仮登録・推定1歩・自動移動はしない。
- 方向＋歩数で指示表へ追加し、「みぎ 2：ついかしたよ」と内容を示す。実行は引き続き別発話／タッチのオッケー。
- 数字単独・一息で複数指示・指示とオッケーの同時発話は採用しない。
- トップの5作品の右端三角形は、デリバリズムと同じ `#284f85` に統一。

## 検証の区別

1. `node scripts/test-delivery-speech.mjs`：実モデル辞書で照合済みのトークン、漢数字、行番号、方向のみ、区間外拒否。
2. `node scripts/test-delivery-speech-browser.cjs`：認識結果を注入し、選択色・指示表・表示・行置換・マイクOFF・320×568の配置固定・5つの三角形の計算済み色を確認。
3. 実Vosk日本語モデル：Windows日本語音声合成でローカル生成した「みぎ、に」「ひだり」「にばん」「オッケー」を認識し、それぞれ `右 二` / `左` / `二 番` / `オッケー` と解釈できた。音声は録音・外部送信していない。
4. 実アダプタ結合：Chromeのテスト用マイクへローカルWAVを入力し、本番と同じVoskAdapter・AudioWorklet・DeliverySpeechを経由。「みぎ2」の繰り返しを2行へ追加し、ロボットは動かず、マイクOFF後は増えないことを確認。ローカルではテスト用にモデル取得先を指定し、公開HTTPSでは既定の本番モデル配信先のまま同じ検証を実施して成功。

3・4の音声と実行スクリプト、結果JSONは `.local-tools/delivery/` と `.local-tools/test-delivery-real-{model,adapter}.cjs`。モデル本体・テスト音声は公開ファイルへ含めない。

合成音声での処理成立は確認したが、利用者の実発話やAndroid/iOSでの認識精度を保証するものではない。前回の模擬結果注入だけでは、この文法不具合を検出できていなかった。

公開修正コミット `eb3e23d` のGitHub Pages処理成功と、`delivery/app.js`・`delivery/commands.js`・トップCSS・SWの配信内容一致を確認。公開HTTPSで実アダプタを通した合成音声の繰り返し認識・指示追加・実行待ち・マイクOFFも成功。
