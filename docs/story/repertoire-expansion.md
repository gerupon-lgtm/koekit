# 筋と分岐の拡張（2026-09-29）

発案者が承認した「20→40筋、代表5筋に2〜3系統の展開、筋の選び方の改善」を実装する。友人と繰り返し遊んでも、言い回しだけでなく出来事と決着の違いを感じられることが目的。もとのおはなし・めちゃくちゃ・選択材料・操作は維持。LLMや外部生成APIは使わない。

## 内容

こども・おとなそれぞれ、5ジャンル×8筋＝40筋。既存5筋には従来ルートと追加2ルートがあり、分岐込みで50ルート。本文の言い換えの組み合わせ数を、この数には含めない。年齢別に文章を書き分けている。

| ジャンル | 新しい4筋 |
|---|---|
| 冒険 | 勘違いの歓迎／急な代役／交換の寄り道／飛ばない灯り |
| 謎解き | 消えた開幕の音／宛名のない招待状／明日からのメモ／反対向きの証言 |
| ハプニング | 覚えのない表彰／声の出ない案内／いつの間にか行列／崩れたケーキの役目 |
| 不思議 | 願いのレシート／眠っている扉／小さな季節／描きかけの絵 |
| 長い一日 | 乗り遅れた日の寄り道／言葉を運ぶ旅／出発点への贈り物／決めない寄り道 |

| 分岐を追加した筋 | 従来の展開 | 追加ルート1 | 追加ルート2 |
|---|---|---|---|
| 雨から荷物を守る | 布の屋根で運ぶ | 雨宿りで手紙を預かる | 濡れた包み紙に地図が現れる |
| なくなった持ち物 | 保管係から返してもらう | 展示品になり、期間を決めて貸す | 自分が置いた荷台の跡をたどる |
| べたべたになる物 | 風で糊を乾かして剥がす | 紙吹雪の模様を絵に残す | 貼りついた落とし物を持ち主に返す |
| 不思議な音 | 挨拶に返事をする | 音が行進のリズムになる | 音が雨を予告していると分かる |
| 届け先が分からない | 受け取り係を訪ねる | 呼びかけて、相手に来てもらう | 受取人が自分だったと分かる |

新しい筋とルートには「解決」「目的・意味の変化」「謎や選択が残る」の決着区分を持たせる。後二者では、共通の「困り事は片づいた」という締めは使わず、矛盾しない定番の締めか、そのルート専用の余韻・その後を使う。「おしまい」「めでたし、めでたし」は引き続き登場する。

## 組み立て

- `coherent-expansion.js`：新しい20筋。各対象に問題・助言・行動・決着・自分の発見・仲間の発見・寄り道・余韻・その後の9本文を持つ。既存20筋の各段階の言い換えは維持。
- `coherent-branches.js`：5筋の追加10ルート。問題は親の筋と共有し、手がかり以降の8本文をルート単位で定義する。
- `coherent-scenes.js`：既存の各4筋の末尾に追加4筋を合わせる。
- `coherent-story.js`：まず筋、その筋に分岐があればルートを選ぶ。以後は選んだルートの助言／自己発見／仲間の発見、行動、決着、余韻を使う。別ルートの文を混ぜない。

通常／事件から／寄り道の3構成、途中合流、5〜8場面は維持。行動に入ってからは時間・場所を変えない。内部の「問題→手がかり→行動→決着」という段階は継承し、内容は招待、観察、交換、待つこと、目的の変更などにも広げる。一般的な意味理解や、任意の文章をつなぐ汎用エンジンを追加したものではない。

## 筋の選択と保存

旧方式はジャンル内4筋から直近3筋を除くため、履歴が残っていると次が1筋に絞られた。新方式は8筋から直近2筋を除外する。履歴にまだない筋を先に選び、一巡後は残る6筋から選ぶ。最後の登場からそのジャンル内で経過した回数に応じ、重みを `1 + min(16, 経過回数)` にする。古い筋ほど出やすいが、最古の1筋だけに限定しない。

3ルートは直近1ルートを除き、同じ未登場優先と重みづけで選ぶ。初めての一巡後は残る2ルートから選べるため、固定した順番で巡回しない。ジャンル自体は原作の種類を引き継ぐので、全40筋からの独立・均等抽選とは異なる。

筋・ルートの履歴を `koekit.story.settings.replay[audience].repertoire` に分離し、最大160件の固定IDを保存する。IDは `plot/ジャンル/筋ID` と `route/筋ID/ルートID`。文章の最大240件の履歴とは別枠なので、転換文の多い話が筋の履歴を早く押し出すことを防ぐ。未登場とは「保持している履歴内で未登場」であり、無期限の読了記録ではない。

初めて「もうひとつ」を生成するときだけ保存。元の話へ戻す、同じ別版へ戻す、読み上げ直す操作では履歴を追加しない。こども／おとなで分離し、保存不能時もページ内では継続する。

旧版の `a/plot-ジャンル/番号` が文章履歴に残っていれば、当時の20筋の並びから固定IDに移行する。追加ルートがある筋では、従来ルートを読んだことも引き継ぐ。すでに新形式の履歴があるときは移行し直さない。本文・名前・音声は保存しない。

別版は引き続き原作由来の専用乱数を使い、同じ入力と両履歴なら同じ結果になる。原作の乱数や履歴を消費しない。

## 検証と試読

- 原作6,000話・通常入力の別版3,000話の材料保持、表記、構成、再現性。
- 各対象50ルート×60話＝計6,000話を追加生成。全ルートの3発見方法・3結末系統を確認し、実際の手がかり・行動・決着が同じルート由来であることを検査。未解決を解決済みとする締めも検査。
- 旧履歴の移行、対象別分離、履歴上限、初回8筋の未登場優先、一巡後の選択肢6筋、古い候補の重みを確認。
- `verify-variants.cjs`：実リロード後の筋・ルート履歴保持、別版初回だけの保存、原作の保持、切替と読み上げ。
- `verify-release.cjs`：新規2モジュールのキャッシュと、オフライン初回起動・生成・切替。
- [試読集](repertoire-samples.md)：各対象10話と同じ材料による雨の3ルート。`node docs/story/sample-repertoire.mjs` で再生成でき、連続10話の筋の重複なしを確認する。

試読した限り、雨の3ルートの因果はそれぞれ独立してつながる。面白さ・好み・読み上げの自然さは自動検査だけでは判断できない。今後の試遊では「10話で既視感のある筋はいくつあったか」「途中で展開を予想できたか」「もう一度聞きたい話があったか」を確認する。公開結果は [公開記録](deployment.md)。
