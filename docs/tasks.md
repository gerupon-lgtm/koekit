## フェーズ0：音声ルーレットによる認識検証

### T-001 リポジトリ骨組みとメインページ

- **対応**: S-01
- **完了条件**: `index.html`（コエキットのメインページ）と `doubutsu/` への遷移、`manifest.json`、`version.json`（v0.1.0）が存在し、GitHub Pagesで表示される
- **検証**: `gerupon-lgtm.github.io/koekit/` が表示され、アプリへ遷移できる。**異常系**: 存在しないパスで404が出ることを確認

### T-002 フォントの自前配置

- **対応**: デザイントークン（screens.md 1節）
- **完了条件**: M PLUS Rounded 1c の woff2 が `assets/fonts/` にあり、サブセット化されている。`--font-family` がフォールバック付きで定義されている
- **検証**: DevToolsのNetworkでCDNへのフォント要求が発生していないこと。**異常系**: フォント読み込み失敗時にフォールバック書体で表示が崩れないこと

### T-003 PWA化（manifest + Service Worker）

- **対応**: 要件12
- **完了条件**: ホーム画面に追加でき、スタンドアロン起動する。アプリシェル（HTML/CSS/JS/フォント）がキャッシュされオフラインで起動する
- **検証**: 機内モードで起動できる。**異常系**: Service Worker更新時に古いキャッシュが残らない（キャッシュ名に `version.json` の値を使う）

### T-004 クロスオリジン分離の必要性を確認する

- **対応**: 方式C の前提調査
- **完了条件**: vosk-browser が `SharedArrayBuffer`（＝クロスオリジン分離）を必要とするかが判明している。必要な場合は `mini-coi.js` または `coi-serviceworker.js` を設置し、`self.crossOriginIsolated === true` になる
- **検証**: DevToolsで `self.crossOriginIsolated` を確認。**必要だった場合の異常系**: COEP有効下でクロスオリジンのモデル取得がブロックされないこと（配信元にCORSヘッダが必要）。Networkパネルで `blocked:NotSameOriginAfterDefaultedToSameOriginByCoep` が出ないこと
- **注意**: **この結果がT-006・T-007の設計を左右する。先に実施する**

### T-005 音声入力層のインターフェース定義

- **対応**: F-002、要件10.3
- **完了条件**: `src/speech/index.js` が implementation-guide 6節のインターフェースを返す。ゲーム側は方式名を知らない
- **検証**: `node scripts/test-logic.cjs` でモックアダプタを差し替えてもゲーム側が動くこと

### T-006 方式A アダプタ（Web Speech API 既定）

- **対応**: F-002
- **完了条件**: `webspeech.js` が ja-JP で動作し、`result`/`error`/`end` を発火する
- **検証**: Pixel 6a / Chrome で「ストップ」が1回認識される。**異常系**: マイク拒否時に `error` を発火し、アプリが落ちない／オフライン時の挙動を記録する

### T-007 方式B アダプタ（端末内処理）と日本語可否の確認

- **対応**: F-002、要件R-02
- **完了条件**: `SpeechRecognition.available()` で ja-JP の可否を判定し、可能なら `install()` を経て `processLocally: true` で認識できる。**可否いずれでも「判明していること」が完了条件**
- **検証**: Pixel 6a / Chrome で可否を確認し、Chromeのバージョンとともに記録する。**異常系**: 未対応時に方式Aまたは方式Cへフォールバックし、エラーで止まらないこと
- **注意**: **フェーズ0で最初に測る項目**（要件受入条件0-c）

### T-008 方式C アダプタ（Vosk）とモデル配信

- **対応**: F-002、要件10.1
- **完了条件**: vosk-browser を `lib/` に配置し、別ホスティング（**【想定】** Cloudflare）から約48MBのモデルを取得して認識できる。取得済みモデルが Cache Storage に入りオフラインで再利用できる
- **検証**: 初回取得の時間・メモリ・再訪時の読み込みを実測して記録。機内モードで認識できる。**異常系**: モデル取得失敗時に方式Bまたは方式Aへフォールバックし、その旨を画面に示す／取得途中で通信が切れた場合に壊れたキャッシュを残さない
- **注意**: **vosk-browser は最終公開が4年前で保守が止まっている。動作しない場合は速やかに発案者へ報告する**

### T-009 語彙テーブルと照合

- **対応**: F-002、要件8.7
- **完了条件**: `vocabulary.js` が同義語表（データ）を持ち、正規化してから照合する。登録外は一致なしを返す
- **検証**: `TZ=UTC node scripts/test-logic.cjs` — 「みぎ」「ミギ」「右」が right に一致、「道」「みぎがわ」が一致なし、空文字が一致なし。**同義語表をコードを触らずに追加できることを確認**

### T-010 受け付け区間のステートマシン

- **対応**: F-002、F-003、要件8.3
- **完了条件**: `phase.js` が5状態（await_start / await_stop / await_position / await_confirm / result）を持ち、状態ごとに受け付ける語だけをアダプタへ渡す。**result では認識を停止する**
- **検証**: 各状態で対象外の語を発話しても何も起きない。**異常系**: 状態遷移中に認識セッションが落ちても状態が壊れない／`end` で自動再開し再開回数を記録する
- **注意**: **常時認識に変更しない**（implementation-guide 5節・変更禁止5）

### T-011 レベル0（ルーレット）

- **対応**: F-004
- **完了条件**: 「スタート」で数字が切り替わり徐々に加速、「ストップ」で惰性後に停止して出目が確定する。タッチでも同じ操作ができる
- **検証**: 音声のみ・タッチのみの両方で完了する。**異常系**: 連続で「スタート」を発話しても二重に走らない（二重送信の防止）

### T-012 生ログの記録

- **対応**: F-005
- **完了条件**: `LogEntry`（data-model.md 2節）をメモリに記録する。`at` はUTC保持。`rawText` に認識文字列をそのまま残す
- **検証**: 発話・誤発動・登録外の3種が正しい `outcome` で記録される。**異常系**: 画面を閉じてリロードするとログが消えている（永続化していないこと）

### T-013 CSVのクリップボード出力

- **対応**: F-006
- **完了条件**: カンマ区切り・全フィールドをダブルクォートで囲み、内部のダブルクォートを2つ重ねる。時刻はJSTへ変換して出力する
- **検証**: `TZ=UTC node scripts/test-logic.cjs` — 認識文字列にカンマ・ダブルクォート・改行を含むケースで列が崩れない。**日付境界**: UTCで日付が変わる時間帯（JST 9:00前後）とJSTの0時前後・月末月初で、出力される日付がJSTとして正しい。**異常系**: `navigator.clipboard` が使えない場合にテキストエリアへフォールバックする

### T-014 合格ライン判定と計測パネル

- **対応**: F-007、S-07、要件11.1
- **完了条件**: 4指標を算出し合否を表示する。閾値は1箇所の定数にまとめる。方式を切り替えて同条件で比較できる
- **検証**: `node scripts/test-logic.cjs` で既知のログ配列から期待値どおりの指標が出る。**異常系**: ログ0件のときにゼロ除算せず「データなし」を表示する
- **注意**: **閾値は要件0章のB区分。** 実測後の変更は要件11.1の更新と改訂履歴1行の追記で足りる

## フェーズ1：ピタリズム本編

### T-015 カード盤面の表示

- **対応**: F-008、S-04
- **完了条件**: レベル定義（data-model.md 4節）に従い枚数・配置を描画する。**縦画面の3×3が収まる**
- **検証**: レベル1〜5と延長で配置が正しい。**異常系**: 狭い幅（360px相当）でも盤面がはみ出さない／タップ領域が48px以上

### T-016 フォーカス移動（本編）

- **対応**: F-004 の再利用
- **完了条件**: レベルの配置に沿ってフォーカスが移動し、「ストップ」で惰性後に停止する
- **検証**: 各レベルで停止位置が盤面内。**異常系**: 2枚のレベルで往復が単調にならない速度カーブになっていること（A区分）

### T-017 位置語の認識と図示

- **対応**: F-009、screens.md 6節
- **完了条件**: 認識した位置を矢印（中央は中点）で表示する。**文字を出さない**
- **検証**: 9位置すべてで正しい図形が出る。**異常系**: 登録外の発話では図形が変わらない

### T-018 2段階確定によるめくり

- **対応**: F-010、要件C-3
- **完了条件**: 確定語でカードがめくれる。確定待ち区間で位置語を発話すると矢印が変わる（言い直し）
- **検証**: 矢印→確定でめくれる。言い直してから確定すると後の位置がめくれる。**異常系**: 確定語を2回発話しても二重にめくれない
- **注意**: **2段階確定を省略しない**（変更禁止3）。**周囲の音で矢印がすり替わる問題に対策を入れない**（変更禁止7）

### T-019 動物の表示と鳴き声

- **対応**: F-011、S-05
- **完了条件**: めくったカードに動物を表示し鳴き声を鳴らす。**縦横比を維持**（`object-fit: contain`）。再生中は認識が停止している
- **検証**: 鳴き声の再生中に発話しても反応しない。画像が引き伸ばされない。**異常系**: 音声ファイルの読み込み失敗時に無音で続行する／端末がサイレントモードでも進行が止まらない

### T-020 成否判定と回数管理

- **対応**: F-012、要件8.4
- **完了条件**: 動物が表示されたら正解、違うカードをめくったら失敗。**認識されなかった場合はカウントしない。言い直しは失敗ではない。** 5回中3回正解でクリア、届かなければゲームオーバー
- **検証**: `node scripts/test-logic.cjs` — 3回正解で即クリア（4・5回目を待たない）、2正解3失敗でゲームオーバー、認識なしが何回あってもカウントが増えない。**異常系**: 3回目の正解と5回目が同時に成立する境界で二重遷移しない
- **注意**: **ゲームオーバーを廃止・緩和しない**（変更禁止6）

### T-021 レベル遷移

- **対応**: F-013、要件8.6
- **完了条件**: レベル0→1→2→3→4（四隅）→5→延長 の順に進む。**レベル3から5へ飛ばさない**
- **検証**: 全レベルを通しで遷移できる。**異常系**: ゲームオーバー後にタイトルへ戻り、同レベルの続きから再開しない

### T-022 延長ステージ

- **対応**: F-014、要件8.6
- **完了条件**: レベル5クリア後に**自動的に突入**する。以降タイトルから直接選べる。速度が上がる
- **検証**: 自動突入と、2回目以降のタイトルからの選択。**異常系**: 延長ステージでゲームオーバーになってもタイトルから再挑戦できる

### T-023 認定書表示

- **対応**: F-015、S-06
- **完了条件**: クリア時とゲームオーバー時の**両方**で表示する。到達レベルに応じた内容
- **検証**: 各レベルのクリアとゲームオーバーで表示される。**異常系**: レベル0で終了した場合も何かが表示される（何も出ないまま戻さない）
- **注意**: **名称・デザイン・レベル対応・名前入力の有無はすべてA区分**（実装時に決めてよい）

### T-024 タッチ操作の全面対応

- **対応**: F-016、要件C-2
- **完了条件**: **全操作がタッチのみで完結する。** マイク未許可でも全レベルを遊べる
- **検証**: マイク許可を拒否した状態でレベル0から延長まで通せる。**異常系**: 音声認識非対応ブラウザでもエラーで止まらない／音声とタッチを混在させても状態が壊れない
- **注意**: **C区分。この状態を壊す変更をしない**

### T-025 レベル選択

- **対応**: F-017、S-02
- **完了条件**: タイトル画面からレベルを選べる（保護者のフォロー用）
- **検証**: 各レベルへ直接入れる。**異常系**: 未到達のレベルを選べる仕様か否かを決めて実装する（**【想定】** 全レベル選択可）
