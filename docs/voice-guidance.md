# 発話で進むための共通案内（2026-09-26）

発案者依頼：次に発話する言葉を常に分かるようにし、既存4作品と今後の小品で統一する。音声ルーレットの2回目以降のスタート、回転中のストップ、結果からのつぎを含む。

## 表示ルール

- 操作案内は消えるトーストにしない。操作するまで、ボタン付近の黄色い案内帯に残す。発話語は20〜25px・太字、補足は15〜16px。
- 主な進行ボタンはアイコンに加えて「スタート」「ストップ」「オッケー」「つぎ」を表示する。ボタン形状、音声・タッチの入口、2段階確定は維持する。
- 現在実際に受け付ける発話だけを案内する。開始説明の「オッケー」とゲーム開始の「スタート」を区別し、まだ受け付けない「つぎ」を同時に案内しない。
- 認識停止中（減速、演出、記憶提示、CPU待機、画像準備）は「みていてね」等に替える。音声受付を常時化しない。
- マイクOFF・権限拒否・再開中はボタン／盤面のタッチ案内へ切り替える。ON復帰・状態更新でも案内は追従する。
- パス・保存などの一時的な通知は既存トーストを継続する。進行案内とは別の役割。
- 案内のために選択中のマスやゲーム進行を変更しない。案内は操作領域を覆わず、画面の通常配置に含める。小画面では余白と盤面サイズで収める。

## 実装と今後の小品

- 共通部品：`src/ui/voice-guide.js` / `voice-guide.css`。4作品のHTMLからCSSを読み込み、SWでも事前キャッシュする。
- `setVoiceGuide(element, word, action, touch)` に現在有効な語と意味、タッチ時の案内を渡す。語が空なら待機・選択の説明のみ。
- `labelVoiceButton(button, label)` でアイコンを残して表示名を付ける。既存aria-labelは保持。
- 共通PhaseMachineを使う作品は `updatePhaseGuide(phase)` を表示更新から呼ぶ。独自状態機械の作品は同じ基本部品へ明示的に接続する。
- `setMicState` の状態通知・共通マイク設定で音声／タッチ表現を更新する。DOMを観察して進行を推測せず、ゲーム側の確定済み状態を正典とする。
- 新しい小品の受入項目：初回と2回目、開始・停止・選択・確定・結果・再挑戦、マイクON／OFF／拒否、受付休止、320×568での操作領域、オフライン。実際の語彙と表示語の一致を確認する。
- 本作業は表示の改善。受け付け語、タイミング、勝敗・レベル進行の変更は行っていない。
