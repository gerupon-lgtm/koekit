# コエキット 実装ガイド（共通本文）

**このファイルが実装指示の正典。** `CLAUDE.md` / `AGENTS.md` は入口であり、内容はここを参照する。

## 1. プロジェクト概要

**コエキット** — Androidでの音声認識検証を目的としたPWA試作群。GitHub Pagesで公開する。

本リポジトリは器であり、メインページから各アプリへ遷移する。1本目が **ピタリズム**：音声で位置を指定して裏向きカードをめくる未就学児向け知育アプリ。

要件定義書: `docs/requirements.md`（版数1.0）。**機能ID・0章のA/B/C区分は必ずそちらを読む。**

### 開発フェーズ

| | 内容 | 関門 |
|---|---|---|
| **フェーズ0** | 音声ルーレット単体で認識精度を計測 | **合格ライン（要件11.1）を全通過しなければフェーズ1へ進まない** |
| フェーズ1 | レベル1〜5・認定書・延長ステージ | |

成果物としてルーレットはレベル0（練習モード）に吸収される。単体公開しない。

## 2. 技術スタック

- **素のHTML / CSS / JavaScript。ビルド工程なし。** バンドラ・トランスパイラを導入しない
- ES Modules（`<script type="module">`）でファイル分割する
- PWA: `manifest.json` + Service Worker
- 依存ライブラリは **vosk-browser のみ**（`lib/` に配置。CDNからの実行時読み込みはしない＝オフライン対応のため）
- フォント: **M PLUS Rounded 1c を woff2 で自前配置**（サブセット化）。Google Fonts CDNは使わない＝オフライン対応のため
- テスト: 実機確認が主。ロジック部分（語彙照合・CSV生成・合格ライン判定・バージョン同値）はNode実行のスクリプトで検証する

### リポジトリ・公開先

- リポジトリ: `github.com/gerupon-lgtm/koekit`
- 公開URL: `gerupon-lgtm.github.io/koekit/`
- アプリのパス: `/koekit/doubutsu/`（正式名称はピタリズム。公開済みURLの互換性のため維持。要件R-01）

## 5. 変更禁止事項（根拠つき）

**次に触るAIが「改善」として壊しやすい箇所。根拠を読んでから触ること。**

### 要件0章のC区分（発案者との合意なしに変更しない）

1. **公開版で利用者の音声を外部送信する方式を使わない。** 未就学児を含む第三者の音声を外部サーバーへ送る実装にしない。検証段階で発案者本人の声のみを対象に方式Aを使うのは対象外。根拠: シクミラボの方針
2. **タッチのみで全機能が操作できる状態を維持する。** 音声必須の操作を作らない。マイク未許可でも遊べる
3. **2段階確定を省略しない。** 位置語 → 図示 → 確定語 の順序を短縮しない。2026-09-20合意の順番モードでは回答列を番号で図示し、必要数が揃ってから全体を確定する
4. **コロガリズム（別リポジトリの公開作品）のコードを変更しない**

### 検証・議論の末に確定した設計（緩めない）

5. **常時音声認識にしない。** 受け付け区間ごとに認識を開始・停止する（`src/game/phase.js`）。根拠: この区間設計が「鳴き声を認識器が拾う問題」と「区間外の語の誤認識」を同時に解決している。常時認識へ変えると両方が復活する
6. **ゲームオーバーを廃止しない。** 【失効：2026-09-20】5回中3回正解に届かなければ自動でタイトルへ戻す。発案者合意により、ゲームオーバー表示後に同じレベルへ再挑戦、またはタイトルへ戻る。判定自体は維持。根拠: 無制限にやり直せる設計は向上心の妨げになるという発案者の判断。**「やり直せたほうが親切では」という善意の緩和を行わない**
7. **確定待ち区間で周囲の音を位置語として拾う問題に対策を入れない。** 矢印がすり替わっても言い直せるため。根拠: 実環境の音は排除せず遊ぶ側が環境を選ぶという発案者の判断。**善意の作り込みを行わない**
8. **認識されなかった場合を失敗にカウントしない。** 何も起きず試行が成立しない扱い。根拠: 確定語の発話がプレイヤーの承認であり、承認前の状態は結果ではない
9. **文字を画面に使わない**（バージョン・コピーライト表記を除く）。【部分失効：2026-09-20】発案者指定の称号名・作品／モード名・レベル選択の内容／解放条件、順番の結果「ざんねん／こたえ」は文字で表示する。【部分失効：2026-09-26】発案者の明示指示により、各区間の発話案内と進行ボタン名も文字で常設する。盤面は図形・動物・数字を基本とする。根拠: 主利用者が未就学児で文字が読めない

上記5〜9を変更する場合は要件定義書の該当行に【失効】を付し、改訂履歴へ追記する（要件18章の運用）。

## 6. 音声入力層（最重要）

**方式を差し替え可能にすることが、この案件の技術的な核。** コエキットの後続試作へ引き継ぐ共通部品になる。**このアプリ専用の実装にしない。**

```js
// src/speech/index.js が返すインターフェース
{
  name: 'webspeech' | 'webspeech-local' | 'vosk',
  isAvailable(): Promise<boolean>,
  start(vocabulary: string[]): void,   // 区間ごとに受け付ける語を渡す
  stop(): void,
  on('result', (raw: string, elapsedMs: number) => void),
  on('error',  (code: string) => void),
  on('end',    () => void)             // セッション終了。呼び出し側が再開を判断
}
```

| 方式 | 実装 | 位置づけ |
|---|---|---|
| A `webspeech` | Web Speech API 既定 | **検証専用。公開版では使わない**（C区分1） |
| B `webspeech-local` | `processLocally: true`。`SpeechRecognition.available()` で可否確認、`install()` で言語リソース導入 | 有望な代替。**ja-JP / Android での可否をフェーズ0で最初に測る** |
| C `vosk` | vosk-browser（WebWorker） | **本命。** モデル約48MBを別ホスティングから取得 |

**方式Dは不採用**（要件10.2）。実装しない。

### 実機検証で確定した事実（2026-09-16 / Pixel 6a / Chrome 153）

詳細は `docs/field-check-results.md`。実装で必ず守ること。

1. **モデルの詰め方** — Voskモデルは `model/` フォルダを一段かませて tar.gz 化する。
   ```
   unzip vosk-model-small-ja-0.22.zip
   mv vosk-model-small-ja-0.22 model
   tar zcf model.tar.gz model
   ```
   `am` `conf` `graph` を tar の直下に置くと、createModel は成功するが **KaldiRecognizer の生成で失敗**する（`Could not be created` → `Not ready` 連発、結果が出ない）。この失敗は「モデルが読めない」ではなく「認識器が作れない」形で出るので紛らわしい。
2. **クロスオリジン分離は不要** — Vosk は `crossOriginIsolated=false` でも動作した。mini-coi も CORS 設定も入れない（要件T-004の結論）。将来 SharedArrayBuffer 前提のビルドに変える場合のみ再検討。
3. **モデルのキャッシュ更新** — vosk-browser はモデルを Cache Storage にキャッシュする。モデルを差し替えたら、キャッシュを切り替えないと古いモデルが使われ続ける。**モデルURLにバージョンを含める等の更新戦略を実装する**（要件12・T-003・T-028）。
4. **音声の渡し方** — AudioWorklet で取り込み、`AudioBuffer`（16kHz）を作って `acceptWaveform` に渡す。Int16 を直接渡すと `getChannelData is not a function` になる。`ScriptProcessorNode` は使わない。
5. **モデル配信** — Cloudflare R2 の公開URLから、CORS設定なしで github.io から読めた。本番もこの構成を踏襲してよい。

### 実装上の注意

- **認識セッションが落ちたら自動再開する。** Android Chromeは連続認識が途中で終わる。`end` イベントで再開し、再開回数をログに残す
- **区間ごとに開始・停止を繰り返すため、停止処理を毎回踏む。** 安定性はフェーズ0の連続使用指標で測る
- **方式の切り替えはURLクエリまたは設定画面から行えるようにする**（同条件での比較のため）。公開ゲームはVosk／端末内WebSpeechのみ。A・未知の指定はVoskへ正規化し、factoryもAを拒否（2026-09-20 T-029）。方式Aの本人検証は公開ゲームとは分離したprobeで行う。ゲーム側は共通インターフェースを使用する

## 7. 語彙と照合

**登録語との照合で表記揺れを吸収する。** 「上」を含む発話なら何でも上と解釈する実装にしない。登録外の発話・雑音は「何もしない」。

```js
// src/speech/vocabulary.js
// 認識文字列 → 正規化（前後の空白除去・カタカナ/ひらがな統一など）→ 同義語表で照合
```

| 語 | 同義語（初期） |
|---|---|
| start | スタート |
| stop | ストップ、停止 |
| up / down / left / right | 上／下／左／右 |
| center | 中央、真ん中 |
| upleft / upright / downleft / downright | 左上／右上／左下／右下 |
| confirm | 決定、オーケー、オッケー |

**同義語表はデータとして外に出し、コードを触らずに追加できる構造にする。** 根拠: ログの認識文字列を見て後から補強する前提（要件8.7）。

## 8. 日時・タイムゾーン

日時はログの記録のみで扱う。入力欄はない。

- **保存はUTC正規化。** 内部は `Date` のUTC値で保持し、ISO 8601で扱う
- **表示・CSV出力はJSTへ変換する。** タイムゾーンは IANA ID `Asia/Tokyo` で保持する。固定オフセット `+09:00` を埋め込まない
- 利用者環境のタイムゾーンに追従し、取得できない／不定なら `Asia/Tokyo` にフォールバックする
- **禁止**: サーバー・端末のローカル時刻依存、`new Date(文字列)` の暗黙ローカル解釈、固定オフセットのハードコード
- CIおよびロジックテストは **`TZ=UTC` で実行する。** JST依存のロジックが混入していないことを検出する

## 9. バージョン管理

- 形式 `v<MAJOR>.<MINOR>.<PATCH>`。現在版 **v0.1.0**
- 増分規則: MINOR更新時はPATCHを0、MAJOR更新時はMINOR/PATCHを0へ戻す
- **正典は `version.json`。** 反映先は (1) `manifest.json` (2) Service Worker のキャッシュ名 (3) タイトル画面フッタの表示
- **`scripts/check-version.cjs` で全反映先の同値を検証する。** 各リリースで実行し、更新漏れを検出する

## 10. 決定的な処理はスクリプト化する

答えが一意に決まる処理は実装AIに毎回推論させず、`scripts/` のNodeスクリプトで生成・検証し、結果だけを使う。

- `check-version.cjs` — バージョン反映先の同値検証
- `test-logic.cjs` — 語彙照合、CSVエスケープ、合格ライン判定、レベル遷移判定の検証
- `stamp-cache.cjs` — キャッシュバスターの刻印。**各デプロイ前に実行し** `sw.js` の `BUILD` を一意値へ置換する

### キャッシュ方針（キャッシュバスター）

- アプリ本体（HTML/CSS/JS/フォント/アイコン）は SW で **network-first**。オンラインなら常に最新を取得し、
  デプロイごとに自動で最新化される。`APP_CACHE` 名に `BUILD` を含め、旧キャッシュは activate で破棄する
- **Voskモデル（R2・別オリジン・約48MB）は SW 非対象＝キャッシュバスターの対象外**（再取得しない）。
  vosk-browser 側の Cache Storage に任せる
- `lib/vosk/vosk.js`（約5.8MB）は `STATIC_CACHE` に cache-first で保持し、毎デプロイでの再取得を避ける。
  ライブラリ更新時のみ `STATIC_CACHE` の版を上げる

## 11. コマンド

ビルド工程がないため、ローカルは静的サーバーで動かす。

```
npx serve .                 # ローカル確認（HTTPSが必要な機能はhttps推奨）
node scripts/test-logic.cjs
TZ=UTC node scripts/test-logic.cjs
node scripts/check-version.cjs
node scripts/stamp-cache.cjs # デプロイ前: キャッシュバスターを刻印（sw.js の BUILD を更新）→ commit → push
```

**マイクはHTTPSまたはlocalhostでのみ使える。** 実機確認はGitHub Pages（HTTPS）で行う。
**デプロイ手順**: `stamp-cache.cjs` を実行して `sw.js` を更新 → commit → push（GitHub Pages が自動ビルド）。
